# Readability Spec — Accuracy-Preserving Easy Explanation

이 명세는 paper-driller의 최종 노트가 사람이 읽기 쉬운 wiki가 되도록 만든다. 목표는
정확한 기술 용어를 없애는 것이 아니라, 정확한 용어를 유지한 채 쉬운 설명을 덧붙이는 것이다.

## Core Rule

1. **정확성 우선**: 원문이 쓰는 기술 용어, 모델명, 데이터셋명, 수식 기호, 수치, 한계 조건을 보존한다.
2. **대체 금지**: 기술 용어를 쉬운 말로 바꿔치기하지 않는다. 반드시 `기술 용어(쉬운 설명)` 형태로 쓴다.
   - Good: `attention head(문장에서 어느 단어를 더 볼지 나눠 맡는 작은 계산 단위)`
   - Bad: `단어 보는 장치`만 쓰고 attention head를 삭제
3. **불확실하면 표시**: 원문 근거가 부족하면 "원문만으로는 불확실하다" 또는 "보고되지 않았다"라고 쓴다.
4. **비유는 보조만**: 비유는 직관을 돕는 용도다. 원 개념을 왜곡하거나 새 주장을 만들면 안 된다.
5. **조건을 보존**: "어떤 모델/데이터/실험 조건에서만 성립하는가"를 쉬운 설명에서도 남긴다.

## Target Reader

- 똑똑하지만 해당 분야를 처음 보는 독자.
- 중학생도 첫 단락의 큰 그림은 따라올 수 있어야 한다.
- 전문가는 정확한 용어와 수치를 보고 원 논문으로 되돌아갈 수 있어야 한다.

## Style Rules

- 한 문장은 되도록 25어절 이하.
- 한 문단은 되도록 4문장 이하.
- 첫 문장은 결론 또는 역할을 먼저 말한다.
- 추상어만 쓰지 말고 작은 예시를 붙인다.
- "본 논문은", "시사한다", "고찰한다", "효율적이다" 같은 상투 표현을 반복하지 않는다.
- 수치가 있으면 출처를 붙인다. 예: `+3.2 F1 (Table 2)`.

## Required Blocks for Composer

Composer는 deep 모드에서 다음 블록을 생성한다.

```markdown
<<<PLAIN_EXPLANATION>>>
### 쉬운 설명
[5-7문장. 정확한 기술 용어를 유지하고 첫 등장에 괄호 설명을 붙인다. 핵심 비유나 예시는 1개만 사용한다.]
<<<END>>>

<<<WHY_IT_MATTERS>>>
### 왜 중요한가
[3-5문장. 이 결과가 무엇을 바꾸는지, 단 원문 근거 밖으로 확장하지 않는다.]
<<<END>>>

<<<READING_GUIDE>>>
### 먼저 알아둘 말
| 용어 | 쉬운 설명 | 정확성 메모 |
|---|---|---|
| [원문 용어] | [초심자 설명] | [성립 조건/주의점/원문 위치] |
<<<END>>>
```

## Self-Check

- [ ] 기술 용어가 쉬운 말로 대체되지 않고 원 용어가 남아 있다.
- [ ] 첫 등장 기술 용어에는 괄호 설명 또는 `먼저 알아둘 말` 표의 설명이 있다.
- [ ] 쉬운 설명에도 수치, 조건, 한계가 빠지지 않았다.
- [ ] 비유가 원 개념보다 강한 주장을 만들지 않는다.
- [ ] 원문에 없는 실용적 함의나 미래 효과를 단정하지 않는다.
