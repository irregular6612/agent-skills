# 시간 예산

발표 시간은 build 수와 대본 길이로 정해진다. 스토리라인에서 예산을 먼저 정하고, 대본을 쓴 뒤 측정한다.

## 계산 (kit/lib.js)

- 말하는 시간: ko = (한글 음절 + 영어 단어 × 1.5 + 숫자 묶음 × 2) / 280 분, en = 단어 / 140 분.
- build마다 클릭·시선 1.5초 (`CLICK`).
- 대본이 없는 build는 1.5초로 잡힌다. 그래서 대본 전에는 시간이 적게 나온다. 대본 전에는 아래 밀도 기준으로 잡는다.
- 이 값은 리허설 기준이 아니다. 첫 리허설 뒤 실제 시간/예상 시간 비율로 `RATE`를 고쳐 쓴다.

## 스토리라인 단계에서 정할 것

1. 세션 예산 = 주어진 분. 말할 시간은 그 90% (전환·물·질문 여유). 30분이면 27분.
2. 밀도 상한 (기준 덱 89장/35분 = 2.5 build/분, 기준 사례 Session A 83 build/30분 = 2.8/분):
   - build ≤ 2.8 × 분, 아이디어(슬라이드 묶음) ≤ 1.5 × 분.
   - 그림 단계 build는 10–20초, 아이디어 슬라이드는 30–60초로 잡는다.
3. 절별 분 배분 (출발점): 배경·Gap·질문 15–20%, 질문 절들은 근거 양에 비례, Q/A 종합·결론 12–15%. 토론은 따로.
4. `talk.js`의 `sections[*].min`에 적는다. writer는 이 값으로 길이를 맞춘다 (`count.js`).
5. **cut list**: 넘칠 때 먼저 뺄 장을 순서대로 적는다. 곁가지 근거(처리량, 두 번째 그림, 부록성 표)부터.
   표지·`Answer to Qn`·guiding question·결론은 빼지 않는다.

## 대본 뒤

- `node build/build.js` → `out/timing.md`: 절별 build 수·대본 있는 build 수·예상 시간·목표, 세션 합계와 여유/초과.
- 노트 끝의 `[⏱ 18s · 12:40 / 30:00]`은 리허설 때 누적 목표로 쓴다.
- 초과하면 이 순서로: cut list에서 뺀다 → `figSeq` 단계를 합친다(build 수 감소) → 대본을 줄인다. 빨리 말하기로 맞추지 않는다.
- 절 하나만 보려면 `node build/count.js <section>` (manifest만 읽고 pptx는 안 만든다).
