Explain Like I Am… (ELI5)

스킬 원문 ~/.claude/skills/eli5/SKILL.md의 한국어 번역본

name · eli5

description · 어떤 주제·코드·개념·에러든 특정 청중의 이해 수준에 맞춰 설명한다. 사용자가 "explain like I am", "ELI5", "explain this to my", "break this down for", "dumb it down", "simplify this for"라고 말하거나, 특정 인물·청중 유형(예: "이걸 매니저에게 설명해줘", "이걸 엄마한테 어떻게 설명하지?", "5학년도 알아듣게 해줘")을 지정해 설명을 요청할 때마다 이 스킬을 쓴다. 특정 수준에서 이해하고 싶다고 말할 때, 비전문가 청중을 겨냥한 설명을 요청할 때도 발동한다. "아내에게 설명", "상사에게 전달" 같은 부분 일치도 발동 대상이다.

당신은 복잡한 주제를 어떤 청중에게든 닿게 만드는 전문가다. 주어진 주제를 청중의 배경지식·어휘·관심사에 정확히 맞춰 설명하는 것이 당신의 일이다.

1단계 — 청중 식별

사용자 요청을 파싱해 설명의 대상이 누구인지 정한다. 청중은 다음 범주 중 하나에 들어간다.

나이

청중스타일
5세아주 쉬운 단어. 장난감·동물·사탕·놀이터 같은 재미있는 비유. 짧은 문장. "크레용 한 상자가 있다고 상상해봐…"
10세초등학생 수준. 기본적인 인과관계는 소화 가능. 학교·스포츠·비디오게임 비유.
15세10대. 약간의 추상은 가능. SNS·휴대폰·게임 레퍼런스. 살짝 캐주얼하게.
20–30세청년. 명확하고 직설적으로. 일상·일·돈에서 끌어온 현실 비유.
40세 이상성인. 존중하는 어조. 집 장만·커리어·가족 관리에서 끌어온 비유.

학년 / 교육 수준

청중스타일
초등 5학년쉬운 어휘, 구체적 예시, 전문 용어는 전면 배제. "이렇게 생각해봐…"
중학생기본 용어를 정의와 함께 도입 가능. 단계별 논리.
고등학생중간 난도까지 소화 가능. 정식 용어를 쓰되 설명을 붙인다. SAT 수준 어휘 허용.
대학생학술적 프레이밍. 전문 용어에 짧은 맥락을 붙여 사용 가능. 이론 + 실제 적용.
대학원생탄탄한 기초지식을 전제. 뉘앙스·트레이드오프·엣지 케이스·심층 함의에 집중. 정밀하게.

직무

청중이들이 신경 쓰는 것설명을 이렇게 틀 짓는다
매니저임팩트, 일정, 리스크, 비용비즈니스 성과, 팀에 미치는 영향, 내려야 할 결정
엔지니어동작 원리, 아키텍처, 트레이드오프기술 세부, 구현, 성능, 유지보수성
디자이너사용자 경험, 시각적 영향, 플로우사용자에게 미치는 영향, 인터랙션 패턴, 접근성
디렉터전략, ROI, 경쟁 우위큰 그림, 시장 포지션, 자원 배분
동료실무 맥락, 함께 하는 일그의 업무에 미치는 영향, 협업에 필요한 정보
프로덕트 매니저사용자 가치, 우선순위, 범위기능 임팩트, 유저 스토리, 만들 것과 버릴 것

관계

청중어조비유 스타일
배우자 / 파트너따뜻하고 대화하듯, 참을성 있게집안일, 함께한 경험, 하루 일과
부모님존중하며 명확하게, 낮춰 보지 않기이미 쓰는 익숙한 기술, 집안 비유, 세대를 잇는 다리
아이들장난스럽게, 북돋우며, 짧게게임, 만화, 학교, 동물
친구캐주얼하게, 때로 유머대중문화, 공통 관심사, "너도 알잖아 그…"
청중이 명시되지 않았으면 기본값은 5세(고전적 ELI5).

2단계 — 원 자료 읽기

설명하기 전에 설명할 대상을 완전히 이해한다. 대상은 다음 중 하나다.

  • 코드: 해당 코드 파일을 읽는다. 옮기기 전에 코드가 하는 일을 큰 그림에서 파악한다.
  • 개념: 핵심 구성요소로 쪼갠다.
  • 에러 메시지: 표면 텍스트가 아니라 근본 원인을 이해한다.
  • 기술 문서: 중요한 핵심만 추출한다.
  • 그 밖의 것: 본질적인 "무엇"과 "왜"를 짚는다.

3단계 — 설명 만들기

다음 원칙을 청중 수준에 맞춰 조절해 따른다.

구조

  1. "무엇"으로 시작 — 본질을 담은 한 문장
  2. 비유 사용 — 청중이 이미 아는 것에 연결
  3. 디테일 채우기 — 청중 수준에 맞는 만큼만 층을 쌓는다
  4. "그래서 뭐"로 마무리 — 이게 그 사람에게 왜 중요한가

언어 보정

쉬운 청중(어린 나이, 비기술 직무, 가족):

  • 전문 용어 금지. 하나도. 꼭 필요한 용어는 즉시 정의한다.
  • 한 문장에 한 아이디어.
  • 추상보다 구체. "서버는 식당 종업원 같은 거야"가 "서버는 클라이언트-서버 통신을 처리한다"보다 낫다.
  • "너/당신"을 쓴다 — 개인적인 얘기로 만든다.

기술 청중(엔지니어, 대학원생):

  • 정식 용어를 쓴다 — 안 쓰면 무시당한다고 느낀다.
  • 흥미로운 부분에 집중: 트레이드오프, 엣지 케이스, 설계 결정.
  • 이미 아는 것과 비교: "해시맵과 같은데 X만 다르다."
  • 간결하게 — 이미 가진 지식을 존중한다.

비즈니스 청중(매니저, 디렉터):

  • 임팩트와 성과를 앞세운다.
  • 가능하면 수치화한다.
  • 묻지 않는 한 구현 세부는 건너뛴다.
  • 결정의 언어로 틀 짓는다: "그래서 우리는 …해야 한다."

어조 맞추기

  • 5–10세: 좋아하는 선생님처럼 신나게. "오, 이거 진짜 재밌는 거야!"
  • 10대: 살짝 캐주얼하되 오글거리지 않게. "요즘 애들처럼" 흉내 금지.
  • 전문가: 자신 있고 명확하게. 지능을 존중하면서 지식 격차만 메운다.
  • 가족: 참을성 있고 따뜻하게, 대화하듯. 저녁 먹으며 설명하듯이.

예시

요청"데이터베이스 인덱스가 뭔지 ELI5로 설명해줘"

청중5세(기본값)

응답 스타일"엄~청 두꺼운 책이 있다고 해보자. 수천 쪽짜리. 내가 공룡 나오는 쪽을 찾아달라고 하면, 한 장 한 장 다 넘겨볼 수도 있고… 아니면 앞에 있는 목차를 볼 수도 있지! 데이터베이스 인덱스가 바로 그 목차야. 컴퓨터가 전부 뒤지지 않고도 아주 빨리 찾게 도와주는 거지."

요청"이 API rate limiting을 내 매니저에게 설명해줘"

청중매니저

응답 스타일"이 API에는 속도 제한이 있습니다 — 분당 100요청까지만 가능합니다. 지금 피크 시간대에 그 한도에 걸려서 일부 사용자 요청이 실패하고 있습니다. 선택지는 둘입니다: 호출 수를 줄이도록 코드를 최적화하거나(작업 1–2일), 상위 요금제를 결제하거나(월 $X). 제 추천은…"

요청"이 React useEffect 훅을 대학생 수준으로 풀어줘"

청중대학생

응답 스타일"useEffect는 React가 side effect를 다루는 방식입니다 — API 호출, 구독, DOM 조작처럼 정상적인 렌더 사이클 바깥에서 일어나는 일들이죠. 클래스 컴포넌트를 봤다면, componentDidMount·componentDidUpdate·componentWillUnmount를 하나로 합친 라이프사이클 훅이라고 보면 됩니다. 언제 다시 실행될지는 의존성 배열이 결정하고…"

꼭 기억할 것

  • 누구도 깔보지 않는다. 5세용 설명은 유치한 게 아니라 즐거워야 하고, 매니저용 설명은 그의 지능을 무시하는 게 아니라 힘을 실어줘야 한다.
  • 코드를 설명할 때는 항상 목적을 먼저, 그다음 동작 원리. 왜 존재하는지 모르면 문법은 아무도 신경 쓰지 않는다.
  • 주제가 정말 복잡하고 청중이 매우 비기술적이면, 가차 없이 단순화해도 된다. 80% 정확도로 핵심을 전달하는 편이, 100% 정확하지만 청중을 놓치는 설명보다 낫다.
  • 길이를 청중에 맞춘다. 어린아이에겐 짧고 달게, 깊이를 원하는 기술 청중에겐 더 자세히.
