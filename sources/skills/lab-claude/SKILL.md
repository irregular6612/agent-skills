# lab-claude — 연구실 Claude Code에 일 맡기기

## 왜 이렇게 하나

사용자는 계정을 둘로 나눠 쓴다. 개인 계정(이 비서, Hermes)은 사적인 일과 지시를 맡고, **공부와 연구 작업은 연구실 계정**이 한다.
연구실 Claude는 Hermes의 모델로 연결하지 않는다(Anthropic 규정상 구독 계정을 제3자 앱의 모델로 쓰는 것은 문제가 될 수 있다).
대신 공식 Claude Code를 **그대로 한 번 실행해 작업을 맡기고**, 결과 파일만 읽어 온다.

## 언제 쓰나

- 쓴다: 공부 자료·개념 설명 노트, 논문 이해·요약 보조, 오늘 공부할 것 정리, 연구 아이디어·실험 계획 초안, 학술 글 초안,
  코드·데이터를 읽는 연구 작업. 사용자가 "연구실 Claude로", "연구실 계정으로"라고 하면 항상 쓴다.
- 쓰지 않는다: 메일·메신저·일정·금융·주식·집·개인 서류 같은 사적인 일. 이런 내용(메일 본문, 잔고, 연락처 등)을
  연구실 계정으로 보내는 프롬프트에 넣지 않는다.
- 짧은 질문 하나에 쓰지 않는다. 한 번 실행에 시간이 걸리고 연구실 사용량을 쓰므로, 몇 분 이상 걸릴 작업만 맡긴다.

## 실행

```bash
SKILL_DIR="<이 SKILL.md가 있는 폴더>"   # 심볼릭 링크면 실제 경로로
"$SKILL_DIR/scripts/lab_claude.sh" --name <짧은-영문-이름> [--dir <작업 폴더>] [--allow-bash] [--timeout <분>] "<작업 지시>"
# 긴 지시는 표준입력으로: printf '%s' "$PROMPT" | "$SKILL_DIR/scripts/lab_claude.sh" --name ... -
```

- 결과는 `~/Workspace/lab-claude-runs/<시각>-<이름>/`에 남는다: `prompt.md`(맡긴 지시), `result.md`(최종 답), `meta.json`(턴 수·시간·비용 추정), `stderr.log`.
- 출력의 `STATUS=ok`를 확인한 뒤 `RESULT=` 파일을 읽는다. `STATUS=error|timeout`이면 `ERROR=` 줄을 사용자에게 그대로 알리고, 같은 작업을 말없이 반복하지 않는다.
- 기본 도구는 읽기·쓰기·편집·검색·웹 조회다. 명령 실행이 꼭 필요한 연구 코드 작업만 `--allow-bash`를 붙인다.
- `--dir`을 주면 그 폴더에서 작업한다(예: 연구 저장소). 주지 않으면 실행 폴더 안에서만 작업한다.
- 기본 제한 시간은 30분. 큰 작업은 `--timeout 60`까지.
- 연구실 Claude Code도 같은 gbrain(second brain)을 읽을 수 있다. 사용자에 대한 맥락을 지시문에 길게 붙이지 말고 "brain에서 찾아 참고하라"고 쓴다.

## 지시문 쓰는 법

연구실 Claude는 이 대화를 보지 못한다. 지시문 하나로 완결되게 쓴다.

1. 목표 한 문장과 결과물 형태(예: "Markdown 노트 하나, 2,000자 이내, 한국어").
2. 필요한 입력: 파일 경로, 논문 URL, brain에서 찾을 키워드.
3. 결과를 어디에 쓸지(실행 폴더 안이 기본, Obsidian vault에 써야 하면 정확한 경로).
4. 하지 말 것: 커밋·push·메일 발송·외부 게시 금지. Public/ 블로그 노트를 고치는 일은 사용자가 요청했을 때만.

## 결과 전달

`result.md`를 읽고 사용자에게 핵심만 짧게 전한다. 만든 파일이 있으면 경로를 알려 준다.
아침 브리핑이나 정기 보고에 넣을 때는 연구실 Claude가 만든 내용이라는 점을 한 줄로 밝힌다.

## 하지 않는 것

- 연구실 토큰을 읽거나 출력하거나 다른 곳에 저장하지 않는다(스크립트가 키체인에서 직접 꺼낸다).
- 개인 계정 정보, 메일·금융 데이터를 연구실 작업 지시에 넣지 않는다.
- 연구실 Claude에게 Hermes 대신 사용자와 대화하게 하지 않는다. 한 번에 하나의 작업만 맡기고 결과를 받는다.
