# Stage 1 — Low-level mimic: 글에서 습관 파악

근거: `style_profiling_research.md` §1, §3.0–3.1 (Huang et al. 2024 LIP 체크리스트, Sawant 2026 trait 불안정성,
Russell et al. 2025 전문가 단서). 이 파일은 **Stage 1 서브에이전트에게 그대로 주는 지시문**과 오케스트레이터 절차를 담는다.

## 오케스트레이터 절차

### Stage 0 — 샘플 위생 (오케스트레이터가 직접)
1. **저자 확인**: "이 글을 본인이 직접 썼고, AI·전문 교정을 거치지 않았나요?" 를 묻는다. 남의 글이면 프로필을 만들지 않는다
   (이 스킬은 사용자 **본인** 목소리 재현용).
2. **메타데이터**: 장르, 목적, 독자, 언어, 글쓴이 L1 (사용자가 말한 것만), 출처 경로.
3. **제외**: 남의 인용문, 코드, 표, 수식, 양식 문구는 `sample.md` 에서 뺀다 (원문은 `sample_raw.md` 로 따로 둔다).
4. **계량**: `python3 {S}/stage1_counts.py sample.md --json counts.json` (프로필 폴더 바로 아래). 분석 중간 파일은 `_work/` 에 둔다.
   `ai_signal_hits` 가 비어 있지 않으면 오염 의심 → 사용자에게 교정 전 원본이 있는지 묻는다.
5. **분할**: 300단어(한국어 800자) 이상이면 A 70% / B 30% 로 나눠 A 로 분석하고 B 는 검증용으로 둔다.
   미만이면 나누지 않고 `holdout: none (검증 불가)` 로 기록한다.

### Stage 1b — 해석 패스 3회 (안정성 필터용)
- 같은 지시문(아래 "서브에이전트 지시문")으로 **서로 독립인 3회**를 돌린다. 모델을 섞는다:
  run1 = Anthropic 모델(Agent), run2 = OpenAI 모델(Codex), run3 = 다른 Anthropic 모델 또는 같은 모델의 새 인스턴스.
- 각 run 은 다른 run 의 결과를 보지 않는다. 출력: `_work/stage1_run{k}.md` (≤ 1,500단어).
- Codex: `codex exec -m <model> --skip-git-repo-check --ephemeral -s workspace-write -C "<프로필폴더>" - < prompt` (백그라운드).

### Stage 1c — 병합 (서브에이전트 1회, 아래 "병합 지시문")
출력: `_work/stage1.md` (≤ 1,200단어). 이것이 Stage 2 의 입력이다.
각 쓰기 직후 `python3 {S}/check_lengths.py <파일>` → 넘으면 같은 작성자에게 한 번 줄이기를 요청한다.

## 서브에이전트 지시문 — Stage 1b (run k)

```
너는 문체 분석가다. 대상: {프로필폴더}/sample.md (사용자가 직접 쓴 글, {언어}, {장르}, {N}단어).
계량값: {프로필폴더}/counts.json (스크립트가 센 값. 너는 세지 말고 이 값을 쓴다).
쓸 파일: {프로필폴더}/_work/stage1_run{k}.md 하나만. 다른 파일은 읽기만 한다.
보고는 한국어, 인용은 원문 그대로 `백틱` 안에 (백틱은 샘플 인용 전용, ID·파일 이름은 백틱에 넣지 않는다).
길이: 1,500단어 이하. 표 위주로 쓰고 항목당 인용은 최대 2개. 넘으면 O 등급 항목 → 셋째 인용 → 설명 문장 순으로 뺀다.

규칙
- 내용·주제는 무시하고 형식만 본다 (disregarding differences in topic and content).
- 모든 항목에 sample.md 원문 인용 1–3개를 붙인다. 원문에 글자 그대로 있는 구간만 인용한다. 인용이 없으면 그 항목은 쓰지 않는다.
- 등급은 인상이 아니라 횟수로 정한다:
  H(habit) = 5회 이상 또는 기회의 과반 / T(tendency) = 2–4회 / O(once) = 1회 /
  N(absence) = 0회인데 일반 LLM 출력에서는 흔한 것.
- 양의 지시(H/T)는 반드시 빈도 상한을 단다 ("문단당 1회 이하", "4–5곳 중 1곳"). O 는 지시로 승격하지 않고 "허용" 으로만 둔다.
- 샘플이 짧다({N}단어). 대부분 T/O 가 정상이다. 억지로 H 를 만들지 마라.

체크리스트 (항목마다: 관찰 / 횟수·기회 / 등급 / 인용 / 지시문 초안 / 장르 전이 stable|adapt|drop)
L1-01 문장 길이 분포·burstiness (counts.sent_len 사용. 짧은 문장·긴 문장이 어디에 놓이는지)
L1-02 문단 길이와 문단 개시 방식
L1-03 기능어 프로필 (눈에 띄게 많거나 적은 것만: I/we, so/therefore, which/that ...)
L1-04 문장 첫 토큰과 연결어 (종류, 위치, 쉼표 여부, 과용/과소)
L1-05 구두점 (쉼표율, 괄호와 그 앞 띄어쓰기, 따옴표 종류, 콜론·세미콜론·대시, 마침표 뒤 띄어쓰기)
L1-06 (한국어일 때만) 쉼표 포함 문장 비율, 연결어미 뒤 쉼표, 의존명사 띄어쓰기, 종결어미 체계
L1-07 대소문자·축약·약어·숫자 표기
L1-08 어휘 수준·레지스터 (기본 동사 선호, 같은 단어 반복 vs 동의어 교체, 샘플보다 높은 어휘의 예)
L1-09 개인 고유 표현 (2회 이상 나온 비주제 3–5단어 구만. 1회는 기록만)
L1-10 구문 패턴 (수동태, 명사화, 분사구문, 문장 끝 -ing 해설구, 문장 조각, 쉼표로 이은 문장)
L1-11 hedge·booster·태도 표지의 표면형과 개수
L1-12 L2 흔적 (비원어민일 때): 아래 표로 따로

L2 흔적 표 (L1-12)
| 유형 | 사례(원문 인용) | 기회 수 | 비율 | 나오는 조건(어떤 자리) | 재현 정책 |
- 유형 예: 관사 누락·오용, 복수 -s, 전치사, 주어-동사 일치, 시제, 셀 수 없는 명사 복수화, 어순, 직역 관용구,
  띄어쓰기 누락, 관계절 동사 누락("which facing") 등. 샘플에 있는 것만.
- 기회 수: 그 오류가 날 수 있었던 자리 수 (예: 관사가 필요한 명사구 수). 대략이면 "약"을 붙인다.
- 재현 정책: "관찰 비율 이하로 재현 가능" / "1회 관찰 — 글 전체 1회 이하" / "재현 금지(의미 손상 위험)".
  정의·변수 의미·수식 도입부 안에서는 언제나 재현 금지.

이 사람이 절대 안 하는 것 (N 목록)
- 샘플에 0회 AND 일반 LLM 출력에 흔한 것만: 대시, 세미콜론, 소제목·글머리표·굵은 글씨, 3항 나열,
  not only/but also, not X but Y, 문장 끝 -ing 해설구, In conclusion/Overall 마무리, 세련된 전환어
  (Moreover, Furthermore, Notably), 방어적 헤지의 독립 문장, 예고 후 나열, 자문자답 + 짧은 단답,
  slogan 한 줄 결론, AI 어휘(delve, crucial, pivotal, underscore, leverage, robust ...), 완벽한 문법(샘플에 오류가 있으면).
- 각 항목에 "샘플 0회, 기회 있었음(예: 나열이 가능한 자리 [인용])" 처럼 근거를 단다.
- 샘플 저자가 실제로 쓴 것은 넣지 않는다.

마지막 절: "가장 확실한 것 5개" (H 또는 N 중에서) 와 "가장 불확실한 것 3개".
```

## 서브에이전트 지시문 — Stage 1c 병합

```
너는 문체 프로필 병합자다. 입력: {프로필폴더}/sample.md, counts.json, _work/stage1_run1.md,
_work/stage1_run2.md, _work/stage1_run3.md. 쓸 파일: {프로필폴더}/_work/stage1.md 하나만. 한국어로.
길이: 1,200단어 이하. 인용은 `백틱` 안에, trait 당 최대 2개. 넘으면 버린 trait 설명 → 중복 인용 → O 등급 순으로 뺀다.

안정성 필터 (반복 추출하면 trait 집합 겹침이 Jaccard 0.22 수준이라는 보고가 있다. 그래서 거른다):
1. 같은 현상을 가리키는 trait 를 run 사이에서 짝짓는다 (표현이 달라도 같은 현상이면 같은 trait).
2. 3회 중 2회 이상 나온 trait 만 남긴다. 단, counts.json 값으로 직접 뒷받침되는 trait 는 1회만 나와도 남긴다.
3. 모든 인용을 sample.md 에서 글자 그대로 찾아본다. 없는 인용은 지우고, 인용이 하나도 안 남은 trait 는 버린다.
4. 등급이 갈리면 횟수 기준을 다시 적용해 정한다. 그래도 애매하면 낮은 등급(H>T>O)을 쓴다.
5. 지시문은 가장 보수적인 빈도 상한을 쓴다. 캐리커처 방지가 우선이다.
6. L2 흔적 표: 유형별로 합치고, 비율은 counts 와 인용으로 다시 확인한다. 새 유형을 만들지 않는다.
7. N 목록: 2회 이상 run 이 낸 것 + counts.json 에서 0 으로 확인되는 것.

출력 구성
## 계량 요약 (counts.json 에서 핵심만)
## 습관 표 | id | 현상 | 횟수/기회 | 등급 | 지시문(빈도 상한 포함) | 인용 | 장르 전이 | 지지 run |
## L2 흔적 표 | 유형 | 인용 | 기회 | 비율 | 조건 | 재현 정책 |
## Never 목록 (근거 포함)
## 버린 trait (개수와 대표 사유 3줄 이내)
## 신뢰도 메모 (샘플 길이, holdout 여부, 어떤 항목이 특히 약한지)
```
