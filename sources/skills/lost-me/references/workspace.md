# 산출물 — 무엇을 어디에 남기는가

## 폴더 구조

```
_workspace/{run_id}/
  00_baseline.md              사용자가 처음 낸 초안. 절대 안 바뀐다.
  00_claims.json              보존 목록 (대조자가 라운드 0에 한 번 뽑은 것)
  round-N/
    rewrite.md                이 라운드의 재작성본
    drops-readability.json    판정자 출력 (드롭 배열)
    drops-academic.json
    drops-humanness.json
    logs/                     판정자 셋의 읽기 로그 원문
      readability.md
      academic.md
      humanness.md
    writer-instruction.md     writer에게 실제로 간 지시 전문
    diff.json                 대조자의 다름 목록
    change-rate.json          변경률 계산 결과
  summary.md
```

`run_id` 는 `YYYY-MM-DD-NNN` 형식이다. 같은 날 두 번째 실행이면 `-002`.

**파일은 드라이버만 쓴다.** 판정자 · 대조자 · writer 는 값만 돌려주고, 드라이버가 받아 적는다.
이유는 하나다 — subagent 가 워크스페이스를 열 수 있으면 이전 라운드 이력이 뒷문으로
들어온다. 판정자에게 이력을 안 주는 것이 이 스킬 전체의 전제다.

**읽기 로그는 워크스페이스에만 남기고 `summary.md` 에 안 올린다.**
판정자 출력이 뭉툭할 때 원인이 읽기 단계인지 발췌 단계인지 가르는 유일한 방법이라
보관은 하되, 사용자가 매번 볼 물건은 아니다.

## 드롭 파일 형식 (`drops-*.json`)

```json
[
  {"quote": "자기보고 채널은 어떤 동기를 스스로 포기의 원인으로 지목하는가를",
   "position": "at",
   "reason": "바로 앞 문단에서 자기보고는 신뢰하기 어렵다고 읽었는데 여기서 세 채널 중 하나로 그대로 들어와 있다. 그 반박을 어떻게 넘겼는지가 안 보여서, 방금 읽은 세 채널 구성이 앞 문단과 어떻게 화해하는지 모르겠다.",
   "blocker": true}
]
```

필드는 이 넷이 전부다. `category` · `severity` · `suggested_fix` · 총평 · 드롭 id · 축 이름을
넣지 마라. 왜 없는지는 `SKILL.md` 의 「되살리지 마라」 절에 하나씩 적혀 있다.

## `diff.json` 형식

```json
[
  {"type": "수치",
   "baseline": "생리 신호(심박, 호흡, 발한)",
   "current": "심박이나 발한 같은 생리 신호",
   "note": "3종 완전 열거가 2종 예시 열거로 바뀌었다."}
]
```

`type` 은 `변조` · `수치` · `인용` · `신설` · `소멸` 다섯 중 하나다.

## `summary.md`

맨 위에 **기준본과 달라진 곳**을 놓는다. 자동 롤백이 없으므로,
저자가 이 목록을 보는 것이 훼손을 잡는 유일한 지점이기 때문이다.

```
## 기준본과 달라진 곳 (N건)

⚠ 수치  생리 신호 3종 → 2종 예시로 강등
⚠ 변조  자극·과제·결정 → 자극·처리·결정
➕ 신설  인지부하 지표 3종 명세
```

유형만 적고 **경중은 안 적는다.** 어느 것이 훼손이고 어느 것이 보강인지가
저자가 판단할 대상이고, 여기에 심각도를 붙이면 그 판단을 미리 대신하는 것이 된다.

그 아래에 이어서 적는다:

- **라운드별 · 축별 드롭 개수 추이** — 총평 필드가 없으므로, 판정자가 뭉툭해졌는지
  아는 유일한 신호가 이 숫자의 움직임이다.
- **라운드별 변경률**
- **아직 남은 blocker** — 독자가 덮은 지점 중 이번에도 안 고쳐진 것.
- **진동 좌표** — 지난 라운드에도 독자가 멈췄던, 그대로 살아남은 구절.
- **겹침 그룹** — 여러 판정자가 같은 문장을 잡은 경우. 사유를 **나란히** 싣는다.
  셋이 서로 다른 이유로 잡았는지 거의 같은 이유로 잡았는지를 저자가 눈으로 갈라야 한다.
  dry-run에서는 9개 문장 그룹 중 6개가 겹쳤고, 그중 일부는 사유가 사실상 같았다.

진동 좌표와 겹침은 writer 에게는 감춘 정보다. 사용자에게는 보여준다.
**사용자는 다시 쓰는 사람이 아니라 판단하는 사람**이기 때문이다.

## 무엇을 최종본으로 내놓는가

3라운드를 다 쓰고 끝나면 **마지막 라운드의 글**을 돌려준다.
"제일 좋았던 라운드"를 고르지 마라 — 이 스킬에는 점수가 없어서 고를 근거가 없고,
근거 없이 고르면 그게 곧 숨은 점수다. 모든 라운드가 워크스페이스에 남아 있으므로
사용자가 직접 집어 가면 된다.
