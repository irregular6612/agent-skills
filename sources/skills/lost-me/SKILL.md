# lost-me

## 이 스킬이 하는 일

사용자가 쓴 학술 산문 한 덩어리를 받아, 그 글을 처음 읽는 독자가 **어디서 읽기를 그만뒀는지**를
찾아내고 그 지점을 근거로 글을 다시 쓴다. 이것을 최대 세 번 반복한다.

보통의 글 고치기 스킬은 규칙 목록을 갖고 있다 — "한 문단은 3~5문장", "두괄식으로 써라".
이 스킬에는 그런 목록이 없다. 대신 글을 실제로 읽는 사람 셋을 세워 두고,
그들이 멈춘 자리의 좌표만 모은다. **이름이 곧 설계다.** 이름이 출력물을 가리키면
(`quality-gate` 같은 것) 읽는 쪽이 채점표로 퇴행한다. `lost-me` 는 독자의 상태를 가리킨다.
**이름을 바꾸지 마라.**

## 먼저 알아야 할 말 여섯 개

- **드롭(drop)** — 독자가 읽다 멈춘 지점 하나. 글에 있는 짧은 구절 + 그때 독자가 어땠는지.
  예: `"인지부하 채널은 결정 직전 얼마나 오래·깊이 생각하는가를 잡는다"` — *"텍스트만 관측된다고
  한 상태에서 '오래·깊이'를 무엇으로 본다는 건지 감이 안 잡혔다."*
- **판정자(judge)** — 그 독자 역할을 하는 격리된 subagent. 셋 있다. 읽힘 · 학술 · 사람다움.
  서로를 모르고, 이전 라운드도 모른다.
- **blocker** — 드롭 중에서 독자가 거기서 글을 **덮은** 것. 거슬렸지만 계속 읽었으면 아니다.
  이게 0이 되면 루프가 끝난다.
- **대조자(auditor)** — 다시 쓴 글이 원래 글의 주장 · 숫자 · 인용을 바꿨는지만 보는 subagent.
  판단은 안 하고 달라진 곳의 목록만 낸다.
- **덮을-자유 문장** — 판정자에게 주는 독자 정의 끝에 항상 붙이는 한 문장.
  "너는 이 글을 끝까지 읽을 의무가 없다."
- **변경률 가드** — 한 라운드에서 글이 너무 많이 바뀌면 알리거나 멈추는 장치.

## 절대 어기면 안 되는 것 다섯 개

1. **파일은 드라이버(너)만 쓴다.** 판정자 · 대조자 · writer 는 값만 돌려준다.
   subagent 가 워크스페이스를 읽을 수 있으면 이전 라운드 이력이 뒷문으로 들어오고,
   판정자에게 이력을 안 준다는 이 스킬의 전제가 무너진다.
2. **판정자 프롬프트를 실행 시점에 조립하지 마라.** KO/EN 두 벌이 각 판정자 agent 파일에
   전문으로 들어 있다. 언어에 맞는 쪽을 고를 뿐이다.
   조립하면 실제로 판정자에게 간 문안이 어디에도 안 남고, 나중에 판정이 뭉툭할 때
   원인을 문안에서 찾을 수 없다.
3. **덮을-자유 문장은 프리셋에 이미 있어도 중복해서 붙인다.** 사용자가 독자를 자유 문장으로
   갈아끼운 경로에서는 그게 유일한 방어선이다.
4. **보존 대조는 루프를 멈추지 않는다.** 검출만 하고 다름 목록을 낸다. 자동 롤백은 없다.
5. **writer 에게 축 · blocker · 겹침 · 대조 결과를 주지 마라.** 이유는 아래 각 자리에 적었다.

## 언제 이 스킬을 안 쓰나

- 사실이 맞는지 검사해 달라 → 이 스킬은 진위를 안 본다. `iterative-academic-writer`.
- 문체를 다듬어 달라 → 내 문체로 다시 쓰기는 `ditto-writer`, 규칙대로 다듬기는 `paper-section-rewrite`.
- 블로그 · 링크드인 · 마케팅 글 → 이 스킬은 학술 산문 전용이다.

## Phase 0 — 준비

### 1. 한 줄 상태 출력

```
lost-me {ko|en} / run_id: {YYYY-MM-DD-NNN} / 독자: {@adjacent-phd | 사용자 지정}
```

### 2. 언어 감지 — 묻지 마라

앞 500자 기준. 한글이 70% 이상이면 `ko`, ASCII 알파벳이 70% 이상이면 `en`.
한글 본문에 영문 용어가 섞인 글은 본문 언어를 따른다.
`--ko` / `--en` 이 명시되면 감지를 무시한다.

### 3. 독자 정하기

`references/reader.md` 를 읽고 그대로 한다. 요약하면:
사용자가 `독자:` 로 지정하지 않았으면 프리셋 `@adjacent-phd` 를 쓰고,
프리셋이든 자유 문장이든 **끝에 덮을-자유 문장을 이어 붙인다.**

### 4. 워크스페이스 만들기

`references/workspace.md` 의 구조대로 만든다.
사용자 초안을 `00_baseline.md` 로 그대로 복사한다. 이 파일은 끝까지 안 바뀐다.

**입력이 없으면** — 사용자가 초안 없이 "이런 걸 써 줘"로 시작했으면 부수 경로다.
`lost-me-writer` 를 두 문장 이내 지시로 한 번 불러 초안을 만들고,
그 결과를 `00_baseline.md` 로 삼아 정상 경로에 들어간다.
그 지시에 판정자용 네 문단짜리 독자 정의를 넣지 마라 — writer 가 방어적으로 쓴다.

## Phase 1 — 라운드 0: 보존 목록 뽑기

`lost-me-auditor` 를 `MODE=extract` 로 한 번 부른다. 본문은 `00_baseline.md` 내용을
호출문에 그대로 넣는다.

받은 JSON을 `00_claims.json` 으로 저장하고, 사용자에게 **보여준다.**

```
기준본에서 지킬 것: 주장 N건 · 수치 N건 · 인용 N건 (00_claims.json)
이 목록은 라운드 내내 안 바뀝니다. 고치려면 초안을 고쳐 처음부터 다시 시작하세요.
```

**승인을 받지 마라. 확인 게이트를 만들지 마라.** 이건 통보다.
목록을 사용자가 편집할 수 있게 하면 "이건 지킬 필요 없다"는 진위 판단이 들어오는데,
진위는 이 스킬이 안 하는 일이다. 탈출구는 초안을 고쳐 라운드 0부터 다시 도는 것 하나다.

## Phase 2 — 라운드 루프 (최대 3회)

라운드 N의 **현재본**은 N=1이면 `00_baseline.md`, 그 뒤로는 직전 라운드의 `rewrite.md` 다.

### 2-1. 판정자 셋을 동시에 부른다

한 번의 응답 안에서 세 agent 를 같이 띄운다. 순차로 부르면 느리기만 하고 얻는 게 없다.

- `lost-me-judge-readability`
- `lost-me-judge-academic`
- `lost-me-judge-humanness`

각 호출문에 넣는 것: `LANG`, (독자를 지정받았으면) `READER` 블록, 그리고 **현재본 전문**.

넣지 말 것: 이전 라운드 이야기, 다른 판정자 이야기, 저자가 뭘 하려는 글인지,
이게 서론인지 결론인지, 대조 결과. 판정자는 이 글을 처음 보는 사람이어야 한다.

### 2-2. 로그와 드롭을 저장하고, 인용이 진짜인지 확인한다

판정자 응답은 읽기 로그 전문 + 드롭 배열 JSON 이다.
로그는 `round-N/logs/{축}.md`, 드롭은 `round-N/drops-{축}.json` 으로 네가 저장한다.

그다음 반드시:

```bash
# {스킬폴더} 는 이 SKILL.md 가 있는 폴더 (Claude ~/.claude/skills/lost-me, Codex ~/.codex/skills/lost-me)
# {현재본} 은 라운드 1이면 00_baseline.md, 그 뒤로는 round-{N-1}/rewrite.md
python3 {스킬폴더}/scripts/verify_quotes.py \
  {현재본} round-N/drops-*.json
```

`quote` 는 현재본에 **한 글자도 안 틀리고** 있어야 한다. 두 가지를 동시에 하기 때문이다 —
판정자가 없는 구절을 지어냈는지 잡고, 다음 라운드에서 "이 지점이 안 고쳐졌다"를
판정하는 유일한 재료가 된다.

어긋난 게 있으면 그 판정자에게 **한 번만** 다시 요청한다("이 구절이 글에 그대로 없다.
로그에서 실제 구절을 그대로 옮겨 달라"). 두 번째도 실패하면 그 드롭은 버리고
`round-N/logs/` 옆에 버린 사유를 적어 둔다.

dry-run에서는 20건 중 20건이 재요청 없이 통과했다. 이 검사가 자주 걸리기 시작하면
프롬프트가 흔들렸다는 신호다.

### 2-3. 끝났는지 본다

세 축의 드롭 중 `blocker: true` 가 **0건**이면 루프를 끝낸다. Phase 3으로 간다.

blocker 를 개수나 점수로 다루지 마라. 판정자가 이진으로 붙인 것을 그대로 센다.
강도를 받아 임계로 자르는 순간 강도가 점수가 되고 임계가 채점표가 된다.

### 2-4. 재작성 지시를 조립한다

```bash
python3 {스킬폴더}/scripts/assemble.py \
  --text {현재본} \
  --academic round-N/drops-academic.json \
  --readability round-N/drops-readability.json \
  --humanness round-N/drops-humanness.json \
  --prev-blockers round-{N-1}/blocker-quotes.json \
  --lang ko > round-N/writer-instruction.md
```

(`--prev-blockers` 는 라운드 2부터. 직전 라운드에서 `blocker: true` 였던 `quote` 들을
`blocker-quotes.json` 으로 저장해 두면 된다.)

스크립트가 하는 일은 정렬뿐이다. **병합하지 않고, 자르지 않고, 라벨을 안 붙인다.**
왜 그런지는 스크립트 맨 위 주석에 적혀 있다. 요약하면:

- **blocker 를 표시하지 않고 순서로만 앞에 둔다.** writer 가 blocker 표시를 보면
  나머지를 흘려보내고, 그러면 사람다움 축이 통째로 죽는다 —
  사람다움 드롭에는 blocker 가 거의 안 붙기 때문이다(dry-run: 7건 중 0건).
- **겹침을 라벨로 표시하지 않는다.** "3개 축이 잡음"은 득표수이고, 득표수는 점수다.
  같은 문장을 잡은 드롭들을 붙여서 배치하는 것으로만 드러낸다.
- **목록 길이에 상한이 없다.** 자를 규칙이 곧 점수다.
  dry-run에서 20건을 받은 writer 는 패치 모드로 가지 않고 글을 통째로 다시 구성했다.

`reason` 은 판정자가 쓴 문장 **그대로** 간다. 요약하지 마라.
요약하는 순간 "독자의 상태"가 "진단"이 되고, 진단에는 처방이 따라붙는다.

### 2-5. writer 를 부른다

`lost-me-writer` 에게 `round-N/writer-instruction.md` 전문과 현재본을 넘긴다.
응답 전체를 `round-N/rewrite.md` 로 저장한다.

**지시는 드롭 목록 + 3문장을 넘지 않는다.** (진동 표시가 붙으면 정확히 3문장이 된다.)
상한을 박아 두는 이유는, 안 박으면 여기가 친절하게 부풀기 때문이다 —
"톤은 학술적으로, 문단당 3~5문장, 두괄식으로…". 그렇게 되면 이 스킬은 자기가
거부한 규칙 카탈로그를 뒷문으로 다시 들인 셈이 된다.

### 2-6. 변경률을 잰다

```bash
python3 {스킬폴더}/scripts/change_rate.py \
  round-{N-1}/rewrite.md round-N/rewrite.md > round-N/change-rate.json
```

(라운드 1은 앞 인자가 `00_baseline.md`.)

기준점은 **직전 라운드**다. 누적 변화는 보존 대조가 이미 보고 있다.

| 결과 | 할 일 |
|---|---|
| `ok` (50% 미만) | 아무 말 없이 진행 |
| `warn` (50~75%) | 사용자에게 한 줄 알리고 진행. 라운드는 소모된다 |
| `halt` (75% 이상) | 이 라운드 재작성을 롤백하고 루프를 멈춘다. 사용자 판단을 받는다 |

**라운드 1은 `halt` 를 면제한다.** 경고만 하고 진행한다.
첫 라운드는 원래 크게 바뀐다 — dry-run 라운드 1이 65.1%였고, 그 재작성은 좋았다.

`halt` 에서 **자동으로 재시도하지 마라.** 변경률 초과는 규칙 위반이 아니라
사람이 봐야 하는 상태다. 다시 돌릴지, 지시를 바꿀지, 여기서 멈출지는 저자가 정한다.

### 2-7. 보존 대조

`lost-me-auditor` 를 `MODE=compare` 로 부른다. 호출문에 `00_baseline.md` ·
`00_claims.json` · 이번 `rewrite.md` 를 넣는다.
받은 다름 목록을 `round-N/diff.json` 으로 저장한다.

**여기서 아무것도 되돌리지 않는다. 루프를 멈추지 않는다. 사용자에게 묻지도 않는다.**
목록은 쌓아 뒀다가 `summary.md` 에 한꺼번에 싣는다.

왜 롤백하지 않는가: 이 스킬에 오는 초안은 정의상 문제가 있는 초안이고,
독자가 막힌 곳을 고치는 유일한 방법이 기준본과 달라지는 것인 경우가 실제로 있다.
dry-run이 두 사례를 남겼다.

- 학술 판정자가 *"이걸 무엇으로 재는지 못 봤다"* 고 멈췄다. 고치는 방법은 무엇으로
  재는지 쓰는 것 하나뿐이고, 그건 기준본에 없던 명제를 새로 넣는 일이다.
- 초안 2문단은 `자극·과제·결정`, 3문단은 `자극·처리·결정` 이었고 두 판정자가 다 걸렸다.
  고치려면 둘 중 하나를 바꿔야 하는데, 그게 명제 변조로 잡힌다.

자동 롤백을 걸면 이 루프는 학술 축에 대해 **구조적으로 수렴하지 못한다** —
고치면 되돌려지고, 되돌리면 같은 드롭이 다시 나오고, 그렇게 라운드를 소진한다.

**대조자의 검출은 믿을 만하다. 못 하는 것은 판단이다.** dry-run에서 위반 10건은
전부 실제로 기준본과 달랐다(오검 0). 다만 그중 다수가 판정자 드롭에 대한 정당한 응답이었다.
달라졌다는 것은 사실이고, 그 다름이 훼손인지 보강인지는 저자만 안다.

**예외를 만들지 마라.** 인용 귀속이 바뀐 것처럼 명백해 보이는 것도 자동으로 되돌리지 마라.
예외 규칙이 생기는 순간 대조자가 다시 판단을 시작한 것이다.

### 2-8. 다음 라운드

이번 라운드의 `blocker: true` 인 `quote` 들을 `round-N/blocker-quotes.json` 으로 저장한다.
다음 라운드의 진동 표시에 쓴다.

라운드 3까지 돌았으면 Phase 3으로 간다.

## Phase 3 — 마무리

`summary.md` 를 쓴다. 구조와 각 항목의 이유는 `references/workspace.md` 에 있다.
맨 위는 **기준본과 달라진 곳**이다. 자동 롤백이 없으므로 저자가 이 목록을 보는 것이
훼손을 잡는 유일한 지점이기 때문이다.

사용자에게 돌려주는 것:

- 마지막 라운드의 글. "가장 좋았던 라운드"를 고르지 마라 — 점수가 없어서 고를 근거가 없다.
- `summary.md` 경로와 워크스페이스 경로.
- 아직 남은 blocker 가 있으면 그 개수와 좌표.

## 되살리지 마라 — 넣으면 설계가 무너지는 것들

전부 **일부러 없는** 것들이다. 있는 게 자연스러워 보이는 게 함정이다.

| 넣고 싶어지는 것 | 넣으면 |
|---|---|
| 드롭에 `category` | 판정자가 라벨 집합을 체크리스트로 역이용한다 |
| 드롭에 `severity` | 점수가 생기고, 임계가 채점표가 된다 |
| 드롭에 `suggested_fix` | 판정자가 독자가 아니라 처방하는 사람이 된다 |
| 드롭에 총평 필드 | "전반적으로 좀 딱딱합니다"가 존재할 자리가 생긴다 |
| writer 에게 blocker 표시 | writer 가 나머지를 흘려보내고 사람다움 축이 죽는다 |
| 겹침을 라벨로 표시 | 득표수가 되고, 득표수는 점수다 |
| 드롭 목록 길이 상한 | 자를 규칙이 곧 점수다 |
| 덮을-자유 append 중복 제거 | 자유 문장 경로에서 유일한 방어선이 사라진다 |
| writer 와 판정자의 독자 문구 통일 | writer 가 방어적으로 쓰고 학술적 밀도가 떨어진다 |
| 재작성 지시 3문장 상한 해제 | 규칙 카탈로그가 뒷문으로 다시 들어온다 |
| 보존 대조의 자동 롤백 | 학술 축에 대해 루프가 수렴하지 못한다 |
| 보존 목록을 사용자가 편집 | 진위 판단이 들어온다. 그건 이 스킬이 안 하는 일이다 |
| 판정자 프롬프트 실행 시점 조립 | 실제로 간 문안이 안 남아 원인 추적이 끊긴다 |
| 세 판정자 프롬프트를 각자 최적화 | 공통 골격이 갈라져 축 간 비교가 무의미해진다 |
| 변경률 임계를 30/50으로 | 첫 라운드마다 멈춘다. dry-run 라운드 1이 65.1%였다 |
| 규칙 카탈로그 참조 (`ko-taxonomy.md` 등) | 로그 질문이 "40개 패턴 중 몇 개"로 바뀐다 |

---

## 알고 써라 — 실행할 때 영향이 있는 것

이 스킬은 아직 완결된 물건이 아니다. 미해결 목록 전체와 그 근거가 된 실측은
같은 폴더의 `README.md` 에 있다. 여기에는 **한 번 돌릴 때마다 영향이 있는 것 세 가지**만 적는다.

- **"통과"의 뜻을 사용자에게 정확히 전해라.** 종료 조건은 blocker 0이지 드롭 0이 아니다.
  실측에서 blocker 0으로 끝났을 때 드롭은 15건 남아 있었다.
  "독자가 다 따라왔다"가 아니라 **"아무도 덮지는 않았다"** 로 말해라.
- **EN 입력이면 루프가 안 돈다.** 영어 판정자는 실측에서 blocker 를 한 건도 안 냈고,
  그래서 라운드 1에서 재작성 없이 끝났다. 좌표 목록은 제대로 나온다.
  영어 글로 시작할 때 이 한계를 먼저 알려라.
- **변경률 임계를 건드리려면** `scripts/change_rate.py` 맨 위 주석을 먼저 읽어라.
  지표 선택과 50/75 임계가 서로 묶여 있다.

## 이 스킬이 안 하는 일

- **진위 검사.** 보존만 본다. 참인지 거짓인지는 `iterative-academic-writer` 의 땅이다.
- **인용이 실존하는 논문인지 확인.**
- **할루시네이션 차단.** 검출해서 저자에게 보여줄 뿐 막지는 않는다.
- **규칙 카탈로그 참조.** 예전 humanize 스킬의 ko-taxonomy.md 를 포함해 어떤 것도 안 본다.
  컨텍스트에는 시간 순서가 없어서 "판정한 다음에만 참조"는 강제할 방법이 없고,
  들어가는 순간 판정자의 질문이 "40개 패턴 중 몇 개에 걸리나"로 바뀐다.
- **기존 학술 스킬 호출.** `iterative-academic-writer` · `paper-section-rewrite` ·
  `paper-readability-review` 를 부르지 않는다. 셋 다 규칙 카탈로그형이라
  부르는 순간 규칙이 역류한다. 공존하는 관계다.
- **블로그 · 링크드인 · 마케팅.** 학술 산문 한정.
