# lost-me — 개발 노트

`SKILL.md` 는 스킬을 **실행하는 쪽**이 읽는 문서다. 이 문서는 스킬을 **고치는 쪽**이 읽는다.
아직 안 풀린 문제, 그 근거가 된 실측, 다음에 할 일을 모아 둔다.

설계 결정의 근거는 `~/.claude/.scratch/lost-me/` 에 있다 — `SPEC.md`(결정), `issues/NN-*.md`(티켓별 근거),
`CONTEXT.md`(용어), `_workspace/`(실측 산출물).

---

## 실측 이력

같은 입력(KDD-UC 한국어 서론, 4문단 1,435자)을 세 번 돌렸다.

| | dry-run (설계 검증) | verify R1 | verify R2 |
|---|---|---|---|
| 실행 주체 | 손으로 조립한 프롬프트 | 실제 스킬 | 실제 스킬 |
| quote 정확 일치 | 20/20 | 16/16 | 15/15 |
| 읽힘 | 5드롭 / blocker 1 | 4드롭 / blocker 0 | 5드롭 / blocker 0 |
| 학술 | 8드롭 / blocker 0 | 7드롭 / blocker 1 | 6드롭 / blocker 0 |
| 사람다움 | 7드롭 / blocker 0 | 5드롭 / blocker 0 | 4드롭 / blocker 0 |
| 겹침 | 9그룹 중 6 | 8그룹 중 4 | 9그룹 중 5 |
| 변경률 | 65.1% | 52.2% | (재작성 없음) |
| 대조자 다름 | 10건 | 32건 | — |

영어 경로는 같은 내용의 영어 서론 시안으로 한 번 돌렸다: 20드롭 / blocker 0 / 정확 일치 20/20 / 겹침 10그룹 중 6.

산출물 위치:
- `_workspace/run-kdd-ko-intro/` — dry-run
- `_workspace/verify-2026-08-30-001/` — 한국어 R1·R2
- `_workspace/verify-en-2026-08-30-001/` — 영어 R1

각 폴더의 `observations.md` 에 그 실행에서 관측된 것이 적혀 있다.

---

## 확인된 것 — 이건 작동한다

- **정확 인용 의무.** 세 번 다 재요청 0회로 통과했다(총 51건). 판정자가 글에 없는 구절을 지어내지 않는다.
- **드롭 좌표의 재현성.** 실행이 달라도 같은 문장이 다시 잡힌다.
  `자기보고 채널은…`, `인지부하 채널은…`, `채널마다 다른 편향을 부여해`,
  `자극·과제·결정` vs `자극·처리·결정` 불일치가 매번 나왔다.
- **사람다움 blocker 0.** 네 번 연속. "여기서 blocker는 드물다"는 프롬프트 한 줄이 억지 blocker를 막는다.
- **겹침이 실제로 신호다.** 세 판정자가 같은 문장을 다른 이유로 잡는 일이 매번 절반 이상의 그룹에서 일어난다.
- **할루시네이션 압력과 그 검출.** writer 는 학술 드롭에 답하려고 매번 없는 내용을 지어낸다
  (verify R1에서는 인용 `[4, 11]` 을 통째로 창작). 대조자가 매번 잡았다.
- **수렴.** verify R2에서 blocker 0으로 종료했다. 라운드 2의 드롭은 라운드 1보다 안쪽 논증에 관한 것으로 바뀌었다.

## 미해결

### 1. blocker 이진 판정이 재현되지 않는다 — 가장 크다

`blocker` 는 "독자가 여기서 글을 덮었다"는 표시다. 종료 조건이 blocker 0건이므로,
이 신호가 흔들리면 라운드 수가 통째로 흔들린다.

세 가지 형태가 전부 관측됐다.

- **축 간** — dry-run에서 같은 문장을 읽힘은 `true`, 학술은 `false` 로 냈다. 사유는 거의 같았다.
- **실행 간** — dry-run은 읽힘이 덮었고, verify R1은 학술이 덮었다. 같은 입력, 같은 프롬프트다.
- **언어 간** — 한국어는 두 번 다 1건, 영어는 0건.

드롭 **좌표**는 재현되는데 blocker 표시만 안 재현된다.
종료 조건을 blocker 말고 다른 것에 걸 수 있는지가 이 스킬의 가장 큰 열린 질문이다.
다만 대안 대부분이 점수 형태라 `SPEC.md` 가 막아 둔 길로 되돌아간다.

### 2. 영어 경로가 루프를 안 돈다

영어 판정자 셋이 blocker 를 한 건도 안 냈다. 종료 조건이 blocker 0이므로
**영어 입력은 라운드 1에서 재작성 없이 끝난다.** 지금은 사실상 읽기 리포트 생성기다.

좌표 품질 자체는 한국어와 같은 수준이었다.
`stimulus, task, decision` 과 `stimulus, processing, decision` 의 가운데 항 불일치를 영어 판정자도 잡았다.

원인 후보 둘, 아직 안 가림:
1. 영어 문안 `true if you put the text down there` 가 한국어 `거기서 덮었으면 true` 보다 문턱이 높다.
2. 영어로 읽는 판정자가 구조적으로 더 보수적이다.

고치려면 판정자 프롬프트를 건드려야 하는데, 그 문안은 `SPEC.md` 5절이
"한 글자도 고치지 마라"로 못박은 부품이다. 세 갈래가 있다.

- 그대로 두고 "영어는 읽기 리포트 전용"으로 문서화한다.
- 영어 문안만 고친다. 대신 KO/EN 골격이 갈라진다 — `SPEC.md` 11절 11번이 금지한 것이다.
- 종료 조건 자체를 바꾼다. 그러면 1번 문제와 같은 문제가 된다.

1번과 2번을 가르는 실험은 어렵지 않다: 같은 영어 글을 문턱 표현만 바꾼 문안으로 다시 돌려 본다.

### 3. 대조자의 다름 목록이 너무 길어질 수 있다

같은 성격의 재작성에서 한 번은 10건, 한 번은 32건이 나왔다. 검출은 두 번 다 정확했다(오검 0).
문제는 분량이다. `summary.md` 최상단의 32줄짜리 목록은 저자가 훑어보고 훼손을 골라내라고
만든 물건으로 기능하지 않는다.

줄이려면 경중을 매겨야 하는데, 경중은 `SPEC.md` 7절이 대조자에게서 걷어낸 바로 그 판단이다.
분량과 무판단을 동시에 만족하는 방법을 아직 못 찾았다.

### 4. 종료가 이르다

verify R2에서 blocker 0으로 끝났을 때 드롭은 15건 남아 있었다.
총 드롭은 16 → 15로 거의 안 줄었다. 설계대로이긴 하다 — 종료 조건은 blocker 0이지 드롭 0이 아니다.

다만 사용자에게 "통과"의 뜻을 정확히 전해야 한다.
**"독자가 다 따라왔다"가 아니라 "아무도 덮지는 않았다"** 이다.

### 5. 저자만 답할 수 있는 드롭

dry-run의 학술 드롭 8건 중 6건이 "근거를 못 봤다"류였다.
writer 는 답을 모르는 채로 그럴듯하게 지어낸다. 매 실행에서 반복됐다.

지금 설계는 그 창작을 대조자가 잡아 저자에게 보여주는 쪽이다.
애초에 writer 에게 안 보내고 저자에게 질문으로 돌려주는 길도 있다.
가르는 규칙이 무엇이어야 하는지 — 판정자 신원만으로 충분한지 — 를 아직 안 정했다.

### 6. 미실측 경로 두 개

- **진동 탐지.** 지난 라운드 blocker 의 quote 가 이번 본문에 그대로 살아남는 경우.
  verify R1의 blocker 좌표는 재작성본에서 사라져서 조건이 안 만들어졌다.
- **3라운드 소진.** 두 라운드 만에 끝나서 못 돌렸다.

둘 다 `scripts/assemble.py` 와 드라이버에 구현은 돼 있고 실행만 안 됐다.

### 7. 변경률 지표가 spec 문구와 다르다

`SPEC.md` 8절은 괄호 안에 "편집거리"라고 적었지만, `scripts/change_rate.py` 의 주 지표는
difflib 의 diff 비율이다. 같은 한 쌍에서 두 값이 68.1% 대 73.5%로 갈린다.
50/75 임계가 dry-run의 65.1% 관측 위에서 정해진 값이라, 편집거리를 쓰면
"지지된다"고 기록된 라운드 1이 중단선에 닿는다. 자세한 근거는 그 스크립트 맨 위 주석에 있다.

임계나 지표를 건드리기 전에 그 주석을 먼저 읽어라.

## 다음에 할 일 — 우선순위 순

1. **영어 blocker 문턱 실험** (미해결 2). 문턱 표현만 바꾼 영어 문안으로 같은 글을 다시 돌린다.
   원인이 문안인지 언어인지 가른다. 이게 갈리면 세 갈래 중 어느 길로 갈지가 정해진다.
2. **다른 글로 한 편 돌리기.** 지금까지의 실측은 전부 같은 서론 한 편이다.
   다른 섹션 · 다른 분야 · SoP 중 하나를 통째로 돌려야 일반화되는지 안다.
3. **종료 조건 재설계 검토** (미해결 1). 1번과 2번의 결과를 보고 판단한다.
   지금 바로 손대면 근거 없이 고치는 것이 된다.
4. **다름 목록 분량** (미해결 3). 2번에서 다른 글의 다름 목록이 몇 건 나오는지 보고 판단한다.
5. **진동·3라운드 경로 실측** (미해결 6). 일부러 조건을 만들어야 한다 —
   예를 들어 writer 가 안 고칠 만한 지점이 있는 글을 고른다.
