# Readability Spec — 고정 독자 intro, 정확성 보존형 쉬운 설명

paper-driller의 모든 preread 노트는 **한 가지 독자**를 위해 쓴다. 난이도 옵션은 없다.
목표는 기술 용어를 없애는 것이 아니라, 정확한 용어를 그대로 두고 옆에 쉬운 설명을 붙이는 것이다.

## 독자 (고정)

- 똑똑하지만 이 분야를 처음 보는 사람. 고등학생, 타분야 대학생, 인접 분야 신입.
- 첫 문단만 읽어도 "이 논문이 무엇을 왜 했는지"를 말할 수 있어야 한다.
- 전문가는 같은 노트에서 정확한 용어·수치·위치를 보고 원문으로 돌아갈 수 있어야 한다.
- 깔보지 않는다. "쉽게"는 "유치하게"가 아니다.

## Core Rule (정확성)

1. **정확성 우선**: 원문의 기술 용어, 모델명, 데이터셋명, 수식 기호, 수치, 한계 조건을 보존한다.
2. **대체 금지**: 용어를 쉬운 말로 바꿔치기하지 않는다. 반드시 `용어(쉬운 설명)` 형태다.
   - Good: `attention head(문장에서 어느 단어를 더 볼지 나눠 맡는 작은 계산 단위)`
   - Bad: `단어 보는 장치`만 쓰고 attention head를 삭제
3. **불확실하면 표시**: 원문 근거가 부족하면 "원문만으로는 불확실하다" 또는 "보고되지 않았다"라고 쓴다.
4. **비유는 보조만**: 비유는 직관을 돕는 용도다. 원 개념을 왜곡하거나 새 주장을 만들면 안 된다. 비유 뒤에는 정확한 용어로 되돌아온다.
5. **조건을 보존**: "어떤 모델/데이터/실험 조건에서만 성립하는가"를 쉬운 설명에서도 남긴다.

## 문장 규칙 (서술 블록)

서술 블록 = READING_DECISION 이유, ONE_MINUTE bullet, CORE_IDEA, WHAT_THEY_DID, LIMITS bullet, TERMS.
표 블록(KEY_EVIDENCE, READING_MAP)과 frontmatter, BibTeX에는 적용하지 않는다.

- 한 문장 **15어절 이하**. 넘으면 둘로 자른다. TERMS의 3단 정의는 단마다 따로 센다. Wiki 링크 줄은 노트 제목을 빼고 센다.
- 한 문장 한 아이디어. 접속사로 두 주장을 잇지 않는다.
- 한 문단 4문장 이하.
- 첫 문장은 결론 또는 역할을 먼저 말한다.
- 추상어 뒤에는 작은 예시를 붙인다. "평가 기준이 흔들린다" 뒤에 "채점자가 매번 바뀌는 셈이다".
- 기술 용어는 **첫 등장에만** `용어(쉬운 설명)`. 두 번째부터는 용어만 쓴다.
- 수치에는 출처를 붙인다. 예: `+3.2 F1 (Table 2)`. 단, 수치의 완전한 서술 자리는 KEY_EVIDENCE 하나뿐이다(preread-v2-spec의 블록 역할 표).

## 사람이 쓴 것처럼 (문체)

- 명사형 종결 금지. "성능 향상 확인." 대신 "성능이 올랐다."
- 상투 표현 금지: "본 논문은", "시사한다", "고찰한다", "효율적이다", "주목할 만하다", "~에 있어서".
- 접속 부사 남발 금지. "또한", "더불어", "한편"이 한 문단에 둘 이상이면 하나를 지운다.
- 같은 문장 구조를 세 번 연속 쓰지 않는다.
- "~할 수 있다"를 "~한다"로 바꿀 수 있으면 바꾼다. 가능성이 아니라 사실이면 단정한다.
- 독자에게 말하듯 쓴다. "이 표를 먼저 보면 된다" 같은 안내가 허용된다.

## 블록별 규칙

| 블록 | 규칙 |
|---|---|
| CORE_IDEA | 순서 고정: (1) "이 논문은 X를 Y로 푼다" 한 문장 → (2) 비유 **정확히 1개**, 한두 문장 → (3) 작동 원리, 용어 괄호 설명 포함 → (4) 누구에게 왜 쓸모인지 한 문장. 3~4문단. |
| ONE_MINUTE | bullet마다 한 문장. 용어 첫 등장은 괄호 설명. Table/Figure/App. 같은 locator를 쓰지 않는다. 숫자를 쓰지 않는다(결론만). |
| WHAT_THEY_DID | bullet 앞에 "왜 이걸 했나" 한 구절. 예: "기준이 흔들리는지 보려고, 세 도메인에서 …". 데이터셋·baseline 구체명은 이 블록에서 한 번. |
| LIMITS | 세 분류 유지. 각 bullet 첫 문장은 "그래서 무엇을 믿으면 안 되는가"로 시작. 수치는 KEY_EVIDENCE 행 번호(C1…)로 참조. empirical이면 실험 반복 횟수와 코드·데이터 공개 여부를 각각 한 줄로 반드시 쓴다(없으면 "보고되지 않았다"). |
| TERMS | 3단 정의: **일상어 한 줄** → 정확한 정의 → 이 논문에서 왜 중요한가. 본문에 이미 괄호 설명이 있는 용어는 넣지 않는다. |
| READING_DECISION 이유 | 독자 적합성만. "X 계열을 연구하면 read, Y가 목적이면 skim". 문제·수치·한계를 다시 쓰지 않는다. |
| Comment (frontmatter) | 80자 이내, 최대 2문장. 문제 한 구절 + 결과 한 구절. ONE_MINUTE를 복제하지 않는다. |

## 예시 (같은 문단, 규칙 적용 전후)

전:
> evaluator를 계속 바꾸면 search utility가 non-stationary해져 HGM류 수렴 보장이 무너진다. RQGM은 시간을 잘라 이 충돌을 피한다.

후:
> AI 에이전트가 스스로 더 나은 버전을 찾아가는 탐색을 상상해 보자. 그런데 "더 낫다"를 판단하는 채점자(evaluator)까지 같이 바꾸면 문제가 생긴다. 채점 기준이 흔들리면 어느 버전이 진짜 나아진 건지 비교할 수 없다. 이 논문의 답은 시간을 학기(epoch)처럼 자르는 것이다. 한 학기 안에서는 채점자를 고정한다(Asm. 2).

수치·위치(Asm. 2)는 그대로다. 바뀐 것은 문장 길이, 비유, 괄호 설명뿐이다.

## deep 모드 전용 블록 (composer)

composer는 deep 모드에서 다음 블록을 추가로 생성한다. 위 문장 규칙과 문체 규칙을 그대로 적용한다.

```markdown
<<<PLAIN_EXPLANATION>>>
### 쉬운 설명
[5-7문장. 정확한 기술 용어를 유지하고 첫 등장에 괄호 설명을 붙인다. 비유는 1개.]
<<<END>>>

<<<WHY_IT_MATTERS>>>
### 왜 중요한가
[3-5문장. 이 결과가 무엇을 바꾸는지, 단 원문 근거 밖으로 확장하지 않는다.]
<<<END>>>

<<<READING_GUIDE>>>
### 먼저 알아둘 말
| 용어 | 쉬운 설명 | 정확성 메모 |
|---|---|---|
| [원문 용어] | [초심자 설명] | [성립 조건/주의점/원문 위치] |
<<<END>>>
```

## Self-Check

- [ ] 기술 용어가 쉬운 말로 대체되지 않고 원 용어가 남아 있다.
- [ ] 첫 등장 기술 용어에 괄호 설명이 있고, 두 번째부터는 용어만 쓴다.
- [ ] 서술 블록의 모든 문장이 15어절 이하다.
- [ ] CORE_IDEA가 "무엇 → 비유 1개 → 원리 → 쓸모" 순서다.
- [ ] ONE_MINUTE에 locator와 숫자가 없다.
- [ ] TERMS가 3단 정의이고, 본문에서 이미 설명한 용어가 없다.
- [ ] 명사형 종결, "본 논문은/시사한다" 류 상투 표현이 없다.
- [ ] 비유가 원 개념보다 강한 주장을 만들지 않는다.
- [ ] 쉬운 설명에도 수치, 조건, 한계가 빠지지 않았다.
- [ ] Comment가 80자·2문장 이내다.
