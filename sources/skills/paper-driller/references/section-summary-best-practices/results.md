# Results Summarization — Best Practices

## Core Principles
1. **객관적 보고 ≠ 해석**: Results는 숫자·사실만. 해석은 Discussion이나 rationale 블록(`발견`)에.
2. **숫자에 출처**: 모든 수치는 `93% (Table 1)`, `+3.2 F1 (Fig. 3)` 처럼 원문 위치 표기.
3. **RQ/hypothesis 단위 조직화**: 연구 질문별로 결과를 묶어 보고.
4. **Descriptive + Inferential**: 평균·표준편차 같은 기술통계와 함께, 유의성/베이스라인 대비도 함께.
5. **부정 결과 포함**: 긍정 결과만 cherry-pick 금지. 논문이 보고한 negative/ablation도 요약에 포함.

## Rationale 블록 — `발견 (Findings)`
- 숫자에서 도출된 핵심 발견 2-3개.
- 각 발견은 "무엇이 → 얼마나 → 어떤 조건에서" 포함.

## Anti-patterns
- "X가 개선되었다" (몇 %? 어디서? 어떤 비교?)
- raw 데이터 나열 (표·그림이 할 일).
- 해석 혼입 ("이것은 X 때문이다" — Discussion 영역).

## Output Checklist
- [ ] 주요 결과 3+ 항목, 각 항목에 숫자+출처
- [ ] 베이스라인/ablation 대비
- [ ] 부정 결과/제한된 케이스 포함
- [ ] `발견` rationale 블록 생성
