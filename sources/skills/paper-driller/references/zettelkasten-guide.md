# Zettelkasten Atomic Insight Guide (원자적 인사이트 추출 가이드)

논문에서 재사용 가능한 원자적 인사이트를 추출하여 Zettelkasten permanent notes 스타일로 정리하는 가이드입니다.

---

## Zettelkasten 핵심 원칙

1. **원자성 (Atomicity)**: 하나의 노트 = 하나의 독립적 인사이트
2. **자기 설명적 (Self-contained)**: 원본 논문 없이도 이해 가능
3. **연결성 (Connectivity)**: 다른 인사이트와의 링크가 가치의 핵심
4. **재사용성 (Reusability)**: 미래 연구/논문에서 직접 활용 가능

---

## 인사이트 추출 기준

논문에서 다음 유형의 인사이트를 추출:

| 유형 | 설명 | 예시 |
|------|------|------|
| **방법론적 인사이트** | 새로운 기법, 트릭, 접근법 | "Attention head pruning이 모델 크기 50% 감소시에도 성능 95% 유지" |
| **이론적 인사이트** | 개념적 발견, 프레임워크 | "Scaling law가 downstream task에서도 선형적으로 적용됨" |
| **실험적 인사이트** | 예상치 못한 결과, 반직관적 발견 | "더 큰 모델이 few-shot에서 오히려 calibration이 낮아짐" |
| **실패/한계 인사이트** | 작동하지 않은 것, 알려진 한계 | "CoT가 산술 이외 추론에서는 일관적 개선을 보이지 않음" |
| **연결 인사이트** | 분야 간 연결, 예상치 못한 유사성 | "Diffusion과 score matching이 동일한 목적함수의 다른 해석" |

## 인사이트 노트 형식

```markdown
### 💡 {인사이트 제목} (한 줄 요약)

**출처**: [[논문 제목]] (저자, 연도)
**유형**: 방법론적 / 이론적 / 실험적 / 실패-한계 / 연결

{인사이트 본문 — 2-4문장으로 핵심을 자기 설명적으로 기술.
원본 논문을 읽지 않은 사람도 이해할 수 있어야 함.
구체적 수치가 있으면 출처와 함께 포함.}

**핵심 조건/맥락**: {이 인사이트가 성립하는 조건. 예: "1B+ 파라미터 모델에서만 관찰됨"}

**연결**: [[관련 인사이트 1]], [[관련 논문 2]]

**활용 가능성**: {이 인사이트를 미래 연구에 어떻게 활용할 수 있는지}
```

## Obsidian 링킹 컨벤션

### 태그 규칙

| 태그 유형 | 형식 | 예시 |
|-----------|------|------|
| 인사이트 유형 | `#insight/{유형}` | `#insight/methodological` |
| 분야 | `#field/{분야}` | `#field/NLP` |
| 신뢰도 | `#confidence/{수준}` | `#confidence/high` |
| 상태 | `#status/{상태}` | `#status/to-verify` |

### 링크 규칙

- **논문 → 인사이트**: 논문 노트의 "원자적 인사이트" 섹션에서 각 인사이트 참조
- **인사이트 → 인사이트**: 관련 인사이트 간 양방향 링크
- **인사이트 → 논문**: 출처 논문 back-link
- **인사이트 → 연구 질문**: 인사이트가 답하거나 제기하는 연구 질문 링크

### 인사이트 파일 네이밍 (독립 파일 생성 시)

```
Insight - {간략 제목}.md
```
예: `Insight - Attention Head Pruning 효율성.md`

## 추출 절차

1. **Phase 1**: 논문의 핵심 주장/발견 목록 작성 (5-10개)
2. **Phase 2**: 각 주장에서 **독립적으로 의미 있는** 것만 선별 (3-5개)
3. **Phase 3**: 선별된 인사이트를 위 형식으로 작성
4. **Phase 4**: 기존 인사이트/논문과의 연결 설정

## 좋은 인사이트 vs 나쁜 인사이트

### ✅ 좋은 인사이트
- "LoRA의 rank 4로도 full fine-tuning의 97% 성능 달성 (Table 3, Llama-7B 기준)" → 구체적, 조건 명시, 출처 있음
- "Self-play가 reward hacking 없이 수렴하려면 reward model도 함께 조정되어야 함" → 조건부 인사이트, 실패에서 배운 교훈

### ❌ 나쁜 인사이트
- "Transformer가 좋은 성능을 보인다" → 너무 일반적, 조건 없음
- "이 논문의 방법이 효과적이다" → 자기 설명적이지 않음, 원본 없이 의미 없음
