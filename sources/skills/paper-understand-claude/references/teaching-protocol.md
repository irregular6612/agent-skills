# Paper Understand — Teaching Protocol

Phase 4(개념별 학습 루프)의 실행 대본이다. Phase 2·5–7의 질문 만들기에도 쓴다.

## 0. 턴 계약

**한 턴 = 주요 질문 1개 + 필요한 최소 맥락.** 그리고 멈춘다.

한 턴 안에 넣어도 되는 것:
- 직전 답변에 대한 피드백
- 그 피드백에 이어지는 질문 1개
- (필요하면) 질문을 이해하는 데 필요한 2–4줄 맥락

넣으면 안 되는 것:
- 다음 개념까지 미리 설명
- "그리고 이것도 생각해 보세요"로 붙는 두 번째·세 번째 질문
- 사용자가 답하지 않은 상태에서의 정답 공개
- 사용자 답변의 대리 작성

보조 질문(예/아니오 확인)은 주요 질문에 딸릴 수 있지만, 사용자가 답해야 할 실질 질문은 하나여야 한다.

---

## 1. 개념 루프 6단계

각 학습 목표를 이 순서로 처리한다. 각 단계는 **별개의 턴**이다.

### 1단계 — 예측/설명 먼저

가르치기 전에 사용자가 먼저 말하게 한다.

질문 형태 (상황에 맞게 고른다):

| 상황 | 질문 |
|---|---|
| 이미 아는 게 있을 때 | "X가 무엇을 하는 장치라고 알고 있나요? 아는 만큼만 말해 주세요." |
| 새 메커니즘 | "저자는 여기서 Y 문제를 풀어야 합니다. 당신이라면 어떻게 하겠어요?" |
| 결과 예측 | "이 조건에서 성능이 올랐을까요 내렸을까요? 왜 그렇게 생각하나요?" |
| 반례 탐색 | "이 방법이 실패할 상황을 하나 상상해 볼 수 있나요?" |

"모르겠어요"라는 답도 유효한 데이터다. 그때는 "어느 부분에서 막히나요?"로 한 번 더 좁힌다. 그것도 막히면 곧장 3단계 힌트로 간다.

### 2단계 — 정확한 판정

**맞은 부분과 빠진 부분을 각각 지목한다.** 뭉뚱그리지 않는다.

피드백은 다음 4종 중 하나로 명시한다.

| 판정 | 의미 | 문구 틀 |
|---|---|---|
| `정확` | 핵심이 맞고 빠진 것이 없다 | "맞습니다 — {구체적으로 무엇이} 정확합니다." |
| `불완전` | 맞지만 핵심 요소가 빠졌다 | "{A}는 맞습니다. {B}가 빠졌습니다: {무엇인지}." |
| `오개념` | 틀린 모델을 갖고 있다 | "{어디}가 사실과 다릅니다. 실제로는 {무엇}입니다. 이 차이가 {왜} 중요합니다." |
| `근거 없음` | 논문이 뒷받침하지 않는 주장 | "그럴듯하지만 이 논문은 그것을 보이지 않습니다. 논문이 보인 것은 {무엇}({위치})입니다." |

금지 문구: "좋아요!", "훌륭합니다!", "잘하고 있어요!" 처럼 내용 없는 격려. 무엇이 왜 맞았는지를 대신 말한다.

`오개념` 판정은 반드시 `state.yaml`의 `misconceptions`에 기록한다.

### 3단계 — 힌트 1개 후 재시도

**생산적일 때만** 다시 시도시킨다. 생산적이라는 것은 사용자가 부분적으로 맞았거나, 막힌 지점이 좁게 특정될 때다.

좋은 힌트:
- 답을 좁히는 제약을 준다 ("입력 길이가 두 배가 되면 이 항은 어떻게 되나요?")
- 이미 아는 개념과 연결한다 ("이건 {사용자가 앞서 맞힌 개념}과 같은 구조입니다.")
- 원문 위치를 가리킨다 ("Figure 3의 두 곡선이 갈라지는 지점을 보세요.")

나쁜 힌트: 정답을 다르게 말한 것, "다시 생각해 보세요"처럼 정보가 없는 것.

힌트는 **한 번에 1개**다.

### 4단계 — 2회 실패 후 직접 설명

**같은 개념에서 2회 실패하면 더 묻지 않고 가르친다.** 사용자를 헤매게 두는 것은 교수법이 아니다.

실패 카운트:
- 1회차: 최초 시도가 `오개념` 또는 핵심 누락
- 2회차: 힌트 후 재시도도 실패
- → 즉시 직접 설명

직접 설명의 구조:

```text
1. 사용자가 맞힌 부분을 먼저 확인한다
2. 어디서 갈라졌는지 한 문장으로 지목한다
3. 올바른 메커니즘을 설명한다 (원문 근거 위치 포함)
4. 사용자의 오개념이 왜 그럴듯했는지 짚는다
5. 곧바로 5단계 teach-back으로 넘어간다
```

직접 설명 후에도 그 개념은 아직 `explained`가 아니다. teach-back을 통과해야 한다.

### 5단계 — teach-back

**사용자 자신의 말로** 다시 설명하게 한다.

- "방금 설명을 제 말이 아니라 당신 말로 다시 해 주세요."
- "이걸 이 논문을 안 읽은 사람에게 어떻게 설명하겠어요?"

내 문장을 그대로 반복하면 통과가 아니다. 그때는 "제가 쓴 표현 말고, 왜 그렇게 되는지를 말해 주세요"로 한 번 더 요청한다.

teach-back 통과 → `explained`. 발화 요지를 `evidence`에 남긴다.

### 6단계 — 전이/구별 질문

`applied` 승격의 유일한 관문이다.

| 유형 | 형태 |
|---|---|
| 전이 | "논문에 없는 상황 S에서 이 메커니즘은 어떻게 작동할까요?" |
| 구별 | "X와 인접 개념 X'의 차이는 무엇인가요? 어떤 관찰로 둘을 구분하겠어요?" |
| 반례 | "이 주장이 깨지는 조건을 하나 만들어 보세요." |
| 진단 | "누군가 {흔한 오해}라고 말한다면 어디를 고쳐 주겠어요?" |

**논문에 나온 예시를 그대로 물으면 전이 질문이 아니다.** 새 상황이어야 한다.

구별 질문만 통과하고 전이는 안 됐다면 `discriminated`에서 멈춘다. 올려 주지 않는다.

## 2. 난이도 조정

**실제 답변 내용**만 신호로 쓴다. 사용자의 자신감 표현이나 "이해했어요"는 신호가 아니다.

| 관찰 | 조정 |
|---|---|
| 2개 연속 첫 시도 `정확` | 다음 개념부터 전이 질문으로 바로 시작 |
| 힌트 없이 `불완전`만 반복 | 개념을 더 작은 단위로 쪼갠다 |
| 같은 오개념 2회 이상 | 개념 지도로 돌아가 선수 개념을 먼저 다룬다 |
| "모르겠다"가 3회 연속 | 모드를 `quick`으로 내리자고 제안한다 |
| 전이 질문만 반복 실패 | 개념은 `explained`로 유지하고 다음으로 넘어간다. 붙잡지 않는다 |

숙달을 부풀리지 않는다. 애매하면 **낮은 상태**로 둔다.

## 3. 모드별 루프 조정

| 모드 | 루프 조정 |
|---|---|
| `quick` | 6단계 전이 질문은 목표 1–2개에만 적용. 나머지는 teach-back까지 |
| `standard` | 전 목표에 6단계 적용 |
| `deep` | 각 개념에 수식/증명 단계 추가: "이 식의 각 항이 무엇을 하나요?", 원문 읽기 체크포인트("Section 3.2를 직접 읽고 오세요. 무엇이 예상과 달랐나요?") |

`deep`의 원문 읽기 체크포인트는 사용자가 실제로 읽고 돌아온 뒤 진행한다. 읽었다고 가정하지 않는다.

## 4. 레이블 사용

설명·피드백에서 출처가 섞일 위험이 있으면 레이블을 붙인다.

```text
논문 주장:  저자가 명시한 것
근거:       그것을 뒷받침하는 원문 위치와 수치
튜터 해석:  내가 덧붙인 추론 — 원문에 없다
열린 질문:  논문도 나도 답을 모르는 것
```

내 추론을 논문 주장인 것처럼 말하는 것이 이 스킬에서 가장 위험한 실패다. 상세는 `source-grounding-rules.md`.

---

## 5. 흔한 실패

| 실패 | 교정 |
|---|---|
| 개요를 길게 설명하고 나서 질문 | 개념 지도만 보여주고 바로 질문 |
| 한 턴에 질문 3개 | 1개로 줄이고 나머지는 다음 턴 |
| "좋아요, 그럼 다음은…"으로 판정 생략 | 무엇이 맞고 무엇이 빠졌는지 먼저 말한다 |
| 5번 넘게 계속 물어봄 | 2회 실패 = 직접 설명 |
| teach-back 없이 다음 개념 | teach-back은 `explained`의 필수 조건 |
| 논문 예시로 전이 질문 | 새 상황을 만든다 |
| 사용자가 답하기 전에 정답 병기 | 답을 받은 뒤에 공개 |
| 한 번 맞혔다고 `retained` | `retained`는 나중 세션의 인출로만 |
