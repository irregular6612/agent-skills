# Paper Understand — Source Grounding Rules

튜터링 중 "무엇이 논문의 말이고 무엇이 내 말인가"를 항상 구분한다. 이 스킬에서 가장 위험한 실패는 **튜터의 추론이 논문의 주장으로 사용자에게 전달되는 것**이다. 사용자는 이 세션에서 배운 것을 나중에 논문의 내용으로 기억한다.

## 1. 네 개의 레이블

```text
논문 주장   저자가 명시적으로 말한 것
근거        그 주장을 뒷받침하는 원문 위치와 관찰/수치
튜터 해석   내가 덧붙인 추론·비유·연결 — 원문에 없다
열린 질문   논문도 나도 답을 모르는 것
```

레이블을 항상 붙일 필요는 없다. **붙여야 하는 경우**는 명확하다.

| 상황 | 레이블 필요 |
|---|---|
| 원문에 없는 비유·직관 설명을 할 때 | ✅ `튜터 해석` |
| 논문이 다루지 않은 함의를 말할 때 | ✅ `튜터 해석` |
| 다른 논문·일반 지식을 끌어올 때 | ✅ `튜터 해석` (+ 출처가 있으면 명시) |
| 저자의 주장을 그대로 전달할 때 | ✅ `논문 주장` (수치가 함께면 `근거` 병기) |
| 답이 없는 질문을 던질 때 | ✅ `열린 질문` |
| 사용자의 답을 판정할 때 | ❌ 판정 4종(`정확/불완전/오개념/근거 없음`)으로 충분 |

**"이 논문에 따르면"이라고 말하려면 실제로 논문에 있어야 한다.** 확인하지 못했으면 "제 추론인데"로 시작한다.

## 1-b. 소스 권위 순서와 `NotebookLM 합성`

근거의 무게는 소스마다 다르다. 충돌하면 위가 이긴다.

```text
1. 원문 논문 / 공식 부록
2. paper-driller canonical preread
3. NotebookLM 답변과 인용        ← 파생 합성물. 1차 근거 아님
4. 관련 Wiki 노트
5. 튜터 배경 지식
```

**NotebookLM도 또 하나의 모델이다.** 인용이 붙어 있다는 사실이 정확성을 보장하지 않는다. 다음은 NotebookLM이 말했다는 이유만으로 사용자에게 전달할 수 없다 — 원문에서 재확인한 뒤에만 쓴다.

- 정확한 수치·점수·비율
- 수식
- Table / Figure / Section / Theorem 식별자
- 저자·소속·venue 귀속

NotebookLM에서 온 재료는 `NotebookLM 합성`으로 출처를 병기한다. 이 표시는 네 레이블을 **대체하지 않고 덧붙는다.**

```text
✅ NotebookLM 합성: 3.2절이 방법의 핵심이라고 정리 → 원문 Section 3.2에서 확인함 → 논문 주장
✅ NotebookLM 합성: 개선 폭 수치 언급 → 원문 미확인 → 사용자에게 제시하지 않음
❌ "논문에 따르면 3.1점 개선입니다" (출처가 NotebookLM 답변뿐)
```

NotebookLM 인용이 preread 소스에만 걸려 있는데 그 주장이 원문 근거를 요구하는 종류(수치·실험 조건·수식·표)라면 `근거 없음`으로 취급하고 원문에서 확인한다.

**"환각 없음(zero hallucinations)"이라고 쓰지 않는다.** 계약은 `references/notebooklm-integration.md`.

## 2. 위치 표기

모든 정량 주장에는 원문 위치 또는 `[위치 미확인]`이 붙는다.

```text
✅ "Table 2에서 3.1점 개선을 보고합니다"
✅ "개선 폭이 보고돼 있지만 [위치 미확인] — 노트의 claim ledger에서 왔습니다"
❌ "약 3점 정도 좋아졌습니다"          (위치 없음)
❌ "Section 4.3의 Table 5에서 3.1점"   (확인 안 한 번호를 지어냄)
```

- 노트의 claim ledger에서 온 값은 그 출처(`노트 claim ledger`)를 밝힌다. ledger 자체가 `[위치 미확인]`이면 그대로 물려받는다.
- Section/Table/Figure/Theorem 번호는 **실제로 본 것**만 쓴다. 그럴듯한 번호를 만들지 않는다.
- 사용자가 위치를 물었는데 모르면 "확인하지 못했습니다"가 정답이다.

## 3. source coverage별 허용 범위

노트 frontmatter의 `source-coverage`가 상한을 정한다. 이 값을 임의로 올리지 않는다.

| coverage | 할 수 있는 것 | 하면 안 되는 것 |
|---|---|---|
| `fulltext` | 전 phase. 수식·증명·실험 세부·ablation | — |
| `section-extract` | 확보된 섹션 범위의 메커니즘·근거 | 미확보 섹션의 방법·수치·실험 조건 |
| `abstract-only` | 문제 정의, 주장의 형태, 개념 오리엔테이션, 무엇을 확인해야 하는지 | **방법 세부, 수치, 비교 대상, ablation, 근거 감사, `deep` 모드 전체** |
| `unknown` | `abstract-only`와 동일 | 동일 + 확인을 권한다 |

`abstract-only`에서 사용자가 "이 방법이 어떻게 작동하나요?"라고 물으면:

```text
초록 범위에서 저자가 말한 것은 {…}입니다.
작동 방식의 세부는 확인된 소스에 없습니다. 지금 답하면 지어내는 것이 됩니다.
원문을 확보하거나 /paper-driller 로 preread 노트를 만든 뒤 이어가겠습니다.
```

세션 상태를 `blocked-by-source`로 두는 것이 없는 근거로 진행하는 것보다 낫다.

## 4. 지어내지 않기

다음은 어떤 상황에서도 만들지 않는다.

- 원문에 없는 수치, 데이터셋 크기, 모델 크기, 하이퍼파라미터
- 확인하지 않은 Section/Table/Figure/Theorem 번호
- 논문이 비교하지 않은 baseline과의 비교
- 저자가 하지 않은 주장
- 저자·소속·venue·연도·식별자
- 존재하지 않는 후속 연구나 반박 논문
- NotebookLM 답변에서만 본 수치·위치·귀속을 원문 근거처럼 제시하는 것

모르는 것에 대한 정답은 **"확인하지 못했습니다"**다. 이것은 튜터로서의 실패가 아니라 정확성이다.

## 5. 사용자의 답이 논문 밖일 때

사용자가 그럴듯하지만 논문이 뒷받침하지 않는 말을 하면 `근거 없음`으로 판정한다.

```text
그 추론 자체는 말이 됩니다. 다만 이 논문이 보인 것은 아닙니다.
논문이 실제로 보인 것은 {무엇}({위치})이고, 당신이 말한 {무엇}은 여기서 검증되지 않았습니다.
이걸 확인하려면 어떤 실험이 필요할까요?
```

- 사용자의 추론을 무시하지 않는다. 근거 상태만 정확히 표시한다.
- 이 교환은 `open_questions`에 `origin: user`로 기록할 수 있다.

## 6. 저자 주장 ≠ 검증된 사실

논문에 쓰여 있다는 것은 저자가 그렇게 주장했다는 뜻이다.

- 저자의 주장을 전달할 때 "논문은 …라고 주장합니다"를 기본 문형으로 쓴다.
- 근거의 강도를 사용자에게 평가시킨다 (Phase 5의 핵심 질문).
- 저자가 인정한 한계와 튜터가 보는 한계를 Phase 6에서 분리한다.

## 7. 자기 점검

턴을 보내기 전에 확인한다.

- [ ] 내가 쓴 수치에 위치 또는 `[위치 미확인]`이 있는가
- [ ] 원문에 없는 설명에 `튜터 해석` 표시가 있는가
- [ ] 확인하지 않은 Section/Table 번호를 쓰지 않았는가
- [ ] `source-coverage`가 허용하지 않는 범위를 다루지 않았는가
- [ ] "논문에 따르면"이라고 쓴 부분이 실제로 논문에 있는가
- [ ] NotebookLM에서 온 재료에 `NotebookLM 합성` 표시가 있고, 수치·식별자를 원문에서 재확인했는가
- [ ] 주요 질문이 1개인가
