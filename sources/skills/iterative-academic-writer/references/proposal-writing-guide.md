# Proposal Writing Guide (연구 제안서 작성 가이드)

논문(Paper)과의 핵심 차이를 먼저 인식한다. 동일한 25원칙을 적용하되 수사적 목표와 독자가 다르다.

| 항목           | 논문 (Paper)                  | 연구 제안서 (Proposal)                   |
| -------------- | ----------------------------- | ---------------------------------------- |
| 시제           | 과거·현재 ("발견했다")        | 미래 ("수행할 예정이다") — 예비 결과 제외 |
| 독자           | 해당 분야 전문가              | 분야 인접 심사위원 (비전문가 포함 가능)  |
| 핵심 설득 목표 | 결과가 유효함을 증명          | 계획이 실현 가능하고 가치 있음을 납득   |
| 주요 증거      | 실험 결과, 수치               | 예비 결과, 팀 역량, 방법론 타당성        |
| 실패 모드      | Hallucination, 과장된 주장    | 실현 불가능한 약속, 측정 불가 목표      |
| IS1 적용       | 기법의 동기 설명              | 접근법을 **선택한** 이유 (대안 대비)    |

---

## 제안서 전용 추가 원칙 (PR1–PR5)

25원칙 외 제안서에만 적용되는 원칙이다. Critic subagent에게 이 원칙도 함께 전달한다.

| ID  | 원칙                      | 위반 예시                                                   |
| --- | ------------------------- | ----------------------------------------------------------- |
| PR1 | **목표 SMART화**          | "성능을 향상시킬 것이다" — 측정 불가 목표                  |
| PR2 | **실현 가능성 증거**      | 예비 연구나 팀 역량 언급 없이 큰 목표만 제시               |
| PR3 | **위험 및 대안 계획**     | 연구 위험을 언급하지 않거나 대안 없이 낙관적 서술만        |
| PR4 | **미래형 시제 일관성**    | "발견했다" 등 과거형 혼용 (예비 결과 서술 구간 제외)       |
| PR5 | **파급효과 구체화**       | "사회에 큰 기여를 할 것이다" — 근거 없는 수사 (NL2와 중복) |

## 한국형 구조 (NRF / IITP 스타일)

### 1. 연구 개요 (Executive Summary, 1페이지 이내)

```
구조:
1. 연구 제목과 핵심 목표 — 한 문장 (두괄식 필수)
2. 연구 필요성 — 해결하려는 문제와 사회적·학술적 의미 (2–3문장)
3. 핵심 연구 내용 — 주요 접근법 요약 (2–3문장)
4. 기대 효과 — 최종 성과물과 파급효과 (1–2문장)
```

**주의**: 개요는 독립적으로 읽혀야 한다. 전문 용어는 한 번만 정의한다.

---

### 2. 연구 목적 및 필요성

```
구조 (두괄식 필수):
1. 핵심 문제 정의 — "X는 Y의 이유로 해결되지 않고 있다" (첫 문장)
2. 기존 연구의 한계 — 구체적 한계점, 수치·사례로 뒷받침
3. 제안 연구의 위치 — 기존 연구와 차별화 포인트
4. 연구의 시급성 — 왜 지금 해야 하는가

규칙:
- 문제는 수치나 사례로 구체화 (예: "기존 방법의 정확도는 X%로 실용 수준 미달")
- "~가 중요하다"만으로 끝나지 않고 "왜 지금이어야 하는가"까지 포함
- PR1: 문제의 규모나 비용을 정량화할 것
```

---

### 3. 국내외 연구 현황

```
구조:
1. 국제 연구 동향 — 3–5개 그룹·논문 소개, 각각 한계 명시
2. 국내 연구 현황 — 국내 수준과 국제 수준 비교
3. 본 연구의 차별성 — "In contrast, 본 연구는 Y에서 차별화된다"

규칙:
- 각 관련 연구 언급 후 반드시 본 연구와의 차이점 1줄 명시
- ✅ "기존 연구는 A를 고려하지 않으나 본 연구는 B로 해결한다"
- ❌ "기존 연구를 보완한다" (구체성 부족)
- UN2 (Compare-contrast) 위반 주의 — 나열만 하고 차이점이 없는 서술 금지
```

---

### 4. 연구 내용 및 방법론

**목표 작성 (PR1 필수)**

```
전체 목표 → 연차별 목표 → 세부 과제 순으로 계층화

SMART 기준:
- Specific: "성능 향상" → "XYZ 벤치마크에서 기존 대비 20% 처리속도 향상"
- Measurable: 수치·지표 명시
- Achievable: 팀 역량·예비 결과로 뒷받침 (PR2)
- Relevant: 연구 목적과의 연결
- Time-bound: 달성 시점 명시 (예: "2년차 2분기까지")
```

**방법론 서술**

```
구조:
1. 연구 방법 개요 — 전략 한 단락 요약
2. 세부 방법 — 각 목표(Q1/Q2/Q3)에 대응
   - 동기(IS1): 왜 이 방법인가 (대안 대비)
   - 접근법: 구체적 수행 내용
   - 예상 결과: 달성 기준
   - 위험 및 대안(PR3): 실패 시 대안 계획 1줄
3. 예비 연구 결과 (있는 경우) — 실현 가능성 증거로 제시 (PR2)

IS1 필수: "왜 이 방법을 선택했는가" — 대안 방법을 한 줄 언급하고 선택 이유 제시
PR3 필수: 각 핵심 방법론에 "주요 위험: X → 대안: Y" 1줄 추가
```

---

### 5. 기대 결과 및 활용 방안

```
구조:
1. 학술적 기여 — 논문 목표 수, 예상 저널·학회 (구체 명시)
2. 기술적 성과 — 특허, 소프트웨어, 데이터셋 (있는 경우)
3. 사회·경제적 파급효과 — 구체적 적용 분야와 예상 영향 (PR5)
4. 연구 결과 확산 — 오픈소스, 공개 데이터 등 계획

파급효과 작성 규칙 (PR5):
- ✅ "XX 산업에서 처리 비용을 N% 절감 가능" (구체 시나리오)
- ❌ "혁신적인 변화를 가져올 것이다" (NL2 + PR5 동시 위반)
- 수치 근거 없는 경제 효과 주장 → FA2 위반
```

---

### 6. 연구 추진 일정

```
구조 (표 또는 간트 차트):
- 연차별 주요 milestone (분기 단위)
- 각 milestone에 측정 가능한 성과 지표 명시 (PR1)
- 연구 목표(4번)와의 대응 관계 표시

예시:
| 기간       | 연구 내용           | 성과 지표                  | 목표 대응 |
| ---------- | ------------------- | -------------------------- | --------- |
| 1년 1분기  | 데이터 수집·전처리  | 데이터셋 X만 건 구축 완료  | Q1        |
| 1년 2분기  | 기반 모델 구현      | 국제학술대회 논문 제출 1편 | Q1        |
| 2년 1분기  | 성능 검증 실험      | 벤치마크 목표치 달성       | Q2        |

일정 현실성 점검 (PR1·PR2):
- 첫 분기에 "알고리즘 개발 완료" 등 비현실적 milestone 금지
- 논문 제출 일정은 실제 학회 데드라인 기준으로 설정
```

## 국제형 구조 (NIH / NSF 스타일)

### Specific Aims (1페이지)

```
1. 해결하려는 문제와 의의 (2–3문장)
2. 현재 접근의 한계와 갭 (2–3문장)
3. 중심 가설 (Central Hypothesis) — 단일 문장
4. Aims 목록 (3개 권장)
   Aim 1. [목표]: [접근법]으로 [기대 결과]를 달성한다.
5. 혁신성과 임팩트 (2–3문장)
```

### Research Strategy: Significance / Innovation / Approach

**Significance**
```
- 문제의 중요성과 규모 (수치 포함)
- 기존 접근의 한계 (구체적)
- 이 연구가 채울 갭
```

**Innovation**
```
- 기존 패러다임과 어떻게 다른가
- 새로운 개념·방법·관점 명시
- IS4: 기존이 놓친 가정을 먼저 드러내고, 그 가정을 바꾸는 것이 본 연구임을 보임
```

**Approach (Aim별 작성)**
```
각 Aim에 반드시 포함:
1. Rationale — 왜 이 Aim이 필요한가 (IS1)
2. Approach — 구체적 수행 방법 (인과 체인 포함, IS2)
3. Expected Outcomes — 기대 결과와 판단 기준
4. Potential Problems & Alternative Approaches (PR3) — 위험·대안 명시

PR3: "Potential Problems"가 없는 Aim은 심사위원 신뢰를 잃는다.
```

## Blueprint 자체 검증 — 제안서 추가 항목

Phase 1 Blueprint 작성 후 논문 체크리스트에 다음을 추가 확인한다:

| 추가 항목                                              | 요건  |
| ------------------------------------------------------ | ----- |
| 모든 목표가 측정 가능한 지표를 포함하는가? (PR1)      | ✅/❌ |
| 예비 연구 결과 또는 팀 역량 증거가 포함되는가? (PR2)  | ✅/❌ |
| 각 핵심 방법에 위험·대안이 계획되었는가? (PR3)        | ✅/❌ |
| 전체 시제가 미래형으로 일관하는가? (PR4)              | ✅/❌ |
| 파급효과가 구체적 시나리오로 서술되는가? (PR5)        | ✅/❌ |

**재작성 임계값**: PR 항목 1개라도 미충족 시 즉시 재작성 (PR1·PR3은 심사 탈락 위험).

## 흔한 함정

| 함정                     | 설명                                                          | 대응 원칙   |
| ------------------------ | ------------------------------------------------------------- | ----------- |
| 지나치게 큰 목표         | "3년 안에 AGI 구현" — 실현 가능성 평가에서 즉시 탈락         | PR1·PR2     |
| 방법론 없는 목표         | "최첨단 AI를 활용한다" — 어떤 기법을 왜 쓰는지 없음          | IS1·PR1     |
| 파급효과 과장            | 근거 없는 경제적 효과 수치                                    | FA2·PR5     |
| 선행연구 요약만           | 차별점 없이 나열 — 본 연구의 위치 불명                        | UN2         |
| 비현실적 일정            | 첫 달에 "알고리즘 개발 완료"                                  | PR1·PR2     |
| 위험 없는 제안           | 모든 것이 계획대로 된다고 서술 — 심사위원 신뢰 상실           | PR3         |
| 과거형 혼용              | 미래 계획을 "~했다" 로 서술                                   | PR4         |
