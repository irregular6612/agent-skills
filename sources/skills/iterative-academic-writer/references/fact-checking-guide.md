# Fact Checking Guide (Hallucination Prevention)

## HARD CONSTRAINT

**Hallucination은 단 하나도 허용하지 않는다.** 모든 사실적 주장은 Fact Base의
`Verified` 또는 허용 범위가 명시된 `User-Attested` 항목과 연결되어야 한다.
연결할 수 없는 정보는 문서에 포함할 수 없다.

`User-Attested`는 사용자가 직접 제공·확인한 개인 경험, 계획, 선호 또는 사용자 소유
데이터에만 사용한다. 외부 논문·기관·인물에 관한 주장은 사용자 진술만으로 검증된 것으로
보지 않는다. 출판용 연구 수치는 원본 결과를 우선 확인하고, 원본이 없으면 사용자가
정확성을 명시적으로 확인했다는 사실을 함께 기록한다.

## Hallucination 유형별 검증 방법

| Hallucination 유형 | 검증 방법 | 도구 |
|-------------------|----------|------|
| **허위 논문 인용** | 논문 존재 여부 및 내용 검증 | WebSearch |
| **잘못된 저자/연도** | 실제 논문 메타데이터 확인 | WebSearch |
| **과장된 성능 주장** | 실험 결과 파일과 직접 대조 | Read tool |
| **존재하지 않는 개념** | 해당 용어/기법 존재 확인 | WebSearch |
| **잘못된 수치/통계** | 원본 데이터와 대조 | Read tool |
| **섹션 간 수치 불일치** | 같은 수치(표본 수, 지표값, 하이퍼파라미터)가 Abstract·Methods·Results·표·그림에서 모두 같은지 대조 | 직접 분석 |
| **허위 인과관계** | 논리 구조 검증 | 직접 분석 |
| **존재하지 않는 기능** | 코드 파일에서 구현 여부 확인 | Read tool |
| **존재하지 않는 API/함수** | 공식 문서 또는 코드베이스 확인 | WebSearch, Read |

## 검증 프로세스

```
문서의 모든 사실적 주장에 대해:

├─ [논문 인용] → WebSearch로 논문 존재 및 내용 확인
│   검증: 논문 존재 여부, 저자, 연도, 내용 일치 확인
│
├─ [수치 데이터] → 원본 데이터와 대조
│   검증: results 파일 또는 원본 논문에서 실제 값 확인
│
├─ [기술적 주장] → 코드/문서에서 직접 확인
│   검증: 코드 파일, config, CLAUDE.md에서 해당 설정/기능 확인
│
├─ [구현 내용] → Git diff 및 코드 확인
│   검증: git log, 해당 파일에서 함수/클래스 존재 확인
│
└─ [개념 정의] → WebSearch로 표준 정의 확인
    검증: 원본 논문 또는 공식 정의와 일치 확인
```

## Fact Base 업데이트

검증 결과와 근거 수준을 명확히 기록:

```
✓ Verified:
- "[사실]" (source: filepath:L행번호 또는 WebSearch: URL)

🟦 User-Attested:
- "[사용자가 직접 제공·확인한 사실]" (source: 사용자 제공 — 독립 검증 안 됨; allowed use: [범위])

✗ HALLUCINATION DETECTED:
- "[주장]" → 실제: [사실] (source)

⚠️ Unverifiable:
- "[주장]" → 출처 불명, 문서에서 제외
```

## Hallucination 발견 시 조치

1. **미검증 명제 전체를 즉시 삭제** — 수치만 지우고 같은 방향의 정성 주장으로 바꾸지 않음
2. **올바른 정보로 대체** (`Verified` 또는 허용된 `User-Attested` 정보만 사용)
3. **검증 불가능한 내용은 문서에서 제외**
4. **재검증 후 다음 iteration 진행**

## 절대 금지 사항

- 검증 없이 수치 언급
- 읽지 않은 논문 인용
- 확인하지 않은 기술 상세/코드 기능 설명
- 추측성 내용을 사실처럼 서술
- 미검증 수치를 삭제한 뒤 "향상했다", "효과가 있었다"처럼 같은 주장을 약하게 남기는 행위
