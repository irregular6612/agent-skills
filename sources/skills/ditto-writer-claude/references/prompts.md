# 프롬프트 템플릿 (Phase 2 루프)

Phase 1(문체·저자 분석) 지시문은 `stage1_low_level.md`, `stage2_author_model.md` 에 있다.
모든 산출물 길이는 `formats.md` 의 "길이 상한" 표를 따르고, 템플릿마다 그 상한 문장이 들어 있다.

`{...}` 를 채워 그대로 보낸다. 채운 전문은 `prompts/<이름>.md` 로 저장한다 (판정이 이상할 때 원인을 문안에서
찾을 수 있게). Codex 는 그 파일을 stdin 으로, Anthropic Agent 는 같은 문안을 `prompt` 로 받는다.

자리표시자: `{WD}` 작업 폴더, `{S}` = `~/.claude/skills/ditto-writer/scripts`, `{PROFILE}` 프로필 폴더,
`{N}` 라운드, `{P}` = N-1, `{EXT}` json|md, `{TH}` 임계값(기본 30), `{SLIPS}` on|off.

## 1. writer — 라운드 1 (`v1.{EXT}` + `writer_r1.md`)

```
너는 이 글의 유일한 작성자(writer)다. 다른 모델들이 매 라운드 이력 없이 결과물만 읽고 블라인드 판독을 한다.
작업 폴더: {WD}. 이 폴더 안의 지정 파일만 쓴다. 원본 복사본·v0*·SAMPLE.md·프로필·블라인드 보고서는 읽기만 한다.

읽을 것
- BRIEF.md (고정 범위, content ledger, 길이, 수식 규칙, 멈춤 규칙)
- {PROFILE}/profile.md (문체·저자 프로필, ≤ 700단어. §5 anchors 는 이 사람이 실제로 쓴 문장이다)
- {PROFILE}/sample.md (샘플 원문 전체)
- v0_context.md, v0.{EXT}
- (있으면) blind_r0_anthropic.md, blind_r0_openai.md — 원문 v0 에 대한 블라인드 판독. 출발점으로만 쓴다.
쓸 것: v1.{EXT}, writer_r1.md 두 개만.

할 일
1. TARGET 단위만 다시 쓴다. v1.json 은 v0.json 과 같은 키, 값은 그 단위의 새 텍스트
   (md 면 v1.md 에 문서 전체, 고정 블록은 글자 그대로).
2. 목표: 프로필의 사람이 쓴 것처럼, 그리고 사람이 쓴 글로 읽히게. 쓰기 전에 anchors 를 소리 내 읽듯 읽고
   그 리듬으로 시작하라. 프로필의 행동 서술(H-02 개념 도입 방식, H-04 확신 정도)을 따르되 샘플의 내용·사례·
   4-gram 이상 구절은 2개 넘게 재사용하지 않는다 (anchor 도 문체용이지 내용용이 아니다).
3. 온도: 글 전체가 샘플과 같은 거칠기여야 한다. 고정된 사용자 부분이 문서 안에 있으면 그 부분과 나머지의
   수준 차이가 가장 큰 단서다. 사용자 부분은 못 고치니 나머지를 그 수준으로 맞춘다.
4. L2 흔적({SLIPS}): on 이면 profile §3 의 재현 가능 유형만, 관찰 비율 이하로, 의미를 해치지 않는 자리에만.
   정의·변수 의미·수식 도입부 안에는 절대 넣지 않는다. 개수 채우기 금지, 희화화 금지. off 면 넣지 않되,
   비원어민다운 연결어·어순을 표준 영어로 다듬지도 않는다. 넣거나 남긴 것은 전부 목록으로 적는다.
5. Never (profile §1) 와 공통 금지: 자문자답 + "Not always." 식 단답, 슬로건 같은 한 줄 결론,
   고른 문장 길이, 예고 후 나열, 쉼표까지 완벽한 3·4항 체크리스트, 방어적 헤지의 깔끔한 독립 문장,
   샘플보다 높은 어휘, 샘플에 없는 em-dash, 본문 속 날 유니코드 수식(p̂, lⱼ, ₋₁ → {MATH_RULE}).
6. Content ledger 의 모든 항목을 남긴다. 수식 도입부 단위는 뒤 수식을 이끄는 끝맺음을 유지. 길이 ±15%.
7. 점검 명령을 돌려 결과를 writer_r1.md 에 붙이고, FAIL 이면 고친다:
   python3 {S}/check_version.py {WD}/v0.{EXT} {WD}/v1.{EXT} --sample {PROFILE}/sample.md
   python3 {S}/stage1_counts.py <대상 텍스트만 모은 임시 파일> --ref {PROFILE}/counts.json
   {DOCX_NOTE}

writer_r1.md 구성 (references/formats.md): 변경 기록 → 의도적 L2 흔적 목록 → content ledger 위치표 →
점검 출력 요약 → 아직 이 사람처럼 안 들리는 문장 (자기 점검. 점수는 선택이며 멈춤 판정에 쓰이지 않는다).
길이: writer_r1.md 는 600단어 이하. 넘으면 우선순위 낮은 것(설명 문장 → 점검 출력 원문)부터 뺀다.
마지막 답(채팅 응답)은 3줄 이하: 쓴 파일 두 개와 check_version 결과 한 줄.
```

`{MATH_RULE}`: docx 면 "`$\hat{p}(r,m,t,l)$`, `$l_{j}$`, `$\Delta S$` 처럼 `$...$` 로 쓰면 Word 인라인 수식이 된다. 또는 말로 풀어라",
md 면 "`$...$` LaTeX 인라인 수식이나 말로", 수식이 없으면 항목을 지운다.
`{DOCX_NOTE}` (docx 일 때만): "`python3 {S}/apply_docx.py {WD}/v0_original.docx {WD}/v1.json /tmp/v1_check.docx` 로 빌드되는지 확인해도 된다 (작업 폴더에 docx 를 쓰지는 마라)."

## 2. writer — 라운드 N≥2 (`vN.{EXT}` + `writer_rN.md`)

```
{라운드 1 의 첫 단락과 동일}

읽을 것: BRIEF.md, {PROFILE}/profile.md, {PROFILE}/sample.md, v0_context.md, v0.{EXT}, v{P}.{EXT}, writer_r{P}.md,
blind_r{P}_anthropic.md, blind_r{P}_openai.md (v{P} 에 대한 블라인드 판독 2건), CHANGELOG.md 의 점수표.
쓸 것: v{N}.{EXT}, writer_r{N}.md 두 개만.

1. 블라인드 지적 판정: 두 보고서의 의심 구간·문단 점수·고칠 제안·"한 사람이 쓴 글인가" 판단을 항목마다
   BRIEF 와 프로필에 비춰 판정한다: 동의 / 부분 동의 / 반대 + 이유 + 이번에 한 일.
   - 리뷰어는 고정 범위·content ledger·프로필을 모른다. 고정 부분(사용자 글, 제목, 수식)을 고치라거나
     내용을 빼라는 제안은 반대하고 이유를 적는다. 대신 그 지적이 드러낸 "차이"를 대상 쪽에서 줄일 수 있는지 본다.
   - "실수를 더 넣어라" 같은 제안은 profile §3 의 유형·상한 안에서만 받아들인다.
   - 두 리뷰어가 같은 구간을 짚으면 가장 강한 신호다. 한 명만 짚은 것은 이유가 설득력 있을 때만.
   - 리뷰어는 매 라운드 새 인스턴스다. 지난 리뷰어의 취향에 맞추지 말고, 여러 라운드에 걸쳐 반복되는 지적을 우선한다.
2. 범위: 어느 리뷰어든 {TH}% 를 넘게 본 대상 문단, high 가 걸린 대상 문단, "한 사람이 아니다"의 근거로 지목된
   대상 문단만 고친다. 나머지는 v{P} 와 글자 그대로 둔다 (변경 기록에 "그대로").
3. 단어 바꾸기로 안 내려가는 문단은 구조를 바꾼다: 개념을 이 사람의 방식(profile H-02)으로 들여오기,
   조건 목록을 이유 뒤 꼬리로, 이름 붙이기 전에 상황부터. "문단마다 기법 하나" 같은 공식은 새 패턴이 된다.
4. 라운드 1 의 2–7번 규칙은 그대로 적용된다.

writer_r{N}.md 구성: 블라인드 지적 판정표 → 변경 기록 → 의도적 L2 흔적 목록 → content ledger 위치표 → 점검 출력 요약 → 자기 점검.
길이: 600단어 이하. 넘으면 동의한 지적의 이유 설명부터 줄이고, 판정표는 한 행 한 줄로. 마지막 답은 3줄 이하.
```

## 3. 블라인드 리뷰어 (매 라운드, 새 인스턴스 2개 병렬)

블라인드 폴더(작업 폴더 밖, 라운드·리뷰어마다 새로 만든 무작위 이름)에 `document.pdf`(docx 대상) 또는
`document.md`, 그리고 `document.txt` 만 둔다. BRIEF·샘플·프로필·이력·목표 점수·"고쳐 쓴 부분이 어디인지"는 주지 않는다.

```
이 폴더의 document.pdf 는 한 사람이 제출한 글이다 (document.txt 는 같은 내용을 글자만 뽑은 것이고,
$...$ 는 원래 수식이다. 서식·수식 모양은 PDF 가 기준이다). 너는 이 글을 처음 보는 외부 독자다.
다른 경로의 파일은 읽지 않는다.

이 글에서 AI 가 쓰거나 다듬었다는 인상을 얼마나 받는지 판단하라. 주관적 인상이지 판독기 결과가 아니다.
1. 전체 AI 인상 %.
2. 문단마다 (첫 5–8단어를 그대로 인용해 지칭) AI 인상 % 와 한 줄 이유. 제목·수식·양식 칸은 점수를 매기지 않아도 된다.
3. 의심 구간을 센 순서로: 원문 그대로 인용 + 왜 그렇게 느꼈는지 + high/medium/low.
4. 사람이 쓴 것으로 보이는 구간과 이유.
5. 한 사람이 처음부터 끝까지 쓴 글로 읽히는가? 예/아니오. 아니오라면 문체나 언어 수준이 바뀌는 지점을 인용으로.
6. 고칠 제안: 의심 구간마다, 그 사람이 쓴 것처럼 읽히려면 무엇을 바꾸면 되는지 구체적으로
   (단어 하나 바꾸기보다 문장 구조·정보 순서·설명 방식 수준으로). 이 글을 쓴 사람의 다른 부분이 근거가 될 수 있다.
한국어로, 전체 600단어 이하로 답한다. 넘으면 low 의심 구간과 사람 같은 구간 설명부터 줄인다
(문단 점수와 high/medium 구간은 빼지 않는다). 마지막 줄은 정확히 이 형식의 한 줄 JSON:
BLIND_JSON: {"overall": NN, "paragraphs": [["첫 5–8단어", NN], ...], "high_spans": ["high 로 판정한 구간 인용", ...], "one_person": true|false}
```

호출:
- OpenAI: `codex exec -m {OPENAI_REVIEWER} --skip-git-repo-check --ephemeral -s read-only -C "<블라인드폴더_o>" -o "{WD}/blind_r{N}_openai.md" - < "{WD}/prompts/blind.md"` (Bash `run_in_background: true`, `timeout: 3600000`)
- Anthropic: Agent(`subagent_type: general-purpose`, `model: {ANTHROPIC_REVIEWER}`), 위 문안에서 "이 폴더" 를 `<블라인드폴더_a>` 절대경로로 바꾸고 끝에
  "파일을 쓰지 말고 답으로만 돌려준다." 를 붙인다. 답 전문을 오케스트레이터가 `{WD}/blind_r{N}_anthropic.md` 로 저장.
- 둘은 한 메시지에서 동시에 띄운다. 같은 인스턴스를 다음 라운드에 다시 쓰지 않는다 (SendMessage 금지).

## 4. 응답 형식이 깨졌을 때

`BLIND_JSON` 이 없거나 파싱이 안 되면 **같은 인스턴스에** 그 줄만 다시 요청하지 말고 (Codex `--ephemeral` 은 이어갈 수 없다)
보고서 본문에서 오케스트레이터가 값을 옮겨 적는다. 문단 점수가 비어 있으면 그 라운드의 그 리뷰어만 새 인스턴스로 다시 돌린다.
